# F07 — Generated and adversarial inputs

Load this guide when the application profile or changed risk selects this family. Record applicability, priority, cheapest convincing layer, execution tier, pass/fail criteria, owner, and evidence. Combine scenarios when one independent test proves several obligations; not-applicable requires a product-specific rationale.

- **F07.01 — Independent invariants**: Independent invariants. Derive generated-test properties from domain requirements, algebraic laws, or external specifications, ensuring the assertion does not merely recompute the implementation under test.
- **F07.02 — Valid domain generators**: Valid domain generators. Build generators that produce meaningful valid records and relationships, encoding genuine domain constraints so generated examples exercise reachable behavior rather than mostly invalid noise.
- **F07.03 — Targeted invalid generators**: Targeted invalid generators. Generate invalid cases by violating one important constraint at a time, verifying the intended rejection while retaining enough valid structure to reach the relevant boundary.
- **F07.04 — Biased edge exploration**: Biased edge exploration. Bias generation toward threshold neighborhoods, repeated values, empty collections, and rare valid combinations, preserving ordinary cases so boundary emphasis does not hide common behavior.
- **F07.05 — Useful shrinking**: Useful shrinking. Ensure shrinking preserves prerequisites and relationships needed to reproduce the defect, producing minimal counterexamples that remain understandable and valid for the tested property.
- **F07.06 — Reproducible counterexamples**: Reproducible counterexamples. Record failing seeds, replay paths, minimized inputs, generator configuration, and relevant code versions, enabling deterministic local reproduction without rerunning an uncontrolled search.
- **F07.07 — Controlled nondeterminism**: Controlled nondeterminism. Control generated clocks, randomness, identifiers, and dependency responses, separating input exploration from environmental nondeterminism so a failing property can be replayed reliably.
- **F07.08 — Round-trip properties**: Round-trip properties. Assert round-trip behavior for parsers and serializers according to declared normalization rules, distinguishing lossless preservation from canonicalization and documenting intentionally discarded information.
- **F07.09 — Idempotence properties**: Idempotence properties. Generate repeated application of normalizers, deduplicators, or idempotent commands, verifying the declared stable result while avoiding assumptions about operations that legitimately accumulate effects.
- **F07.10 — Metamorphic relationships**: Metamorphic relationships. Transform inputs in ways with predictable output relationships, such as permutation, duplication, or unit conversion, explicitly stating the preconditions that make each relationship valid.
- **F07.11 — Conservation properties**: Conservation properties. Generate allocations, transfers, and reconciliations and verify conserved totals, bounded quantities, and permitted rounding discrepancies using independently stated domain constraints.
- **F07.12 — Commutativity boundaries**: Commutativity boundaries. Generate independently applicable operations and compare execution orders, then exercise dependent operations separately so commutativity is asserted only where the product actually promises it.
- **F07.13 — Model-based sequences**: Model-based sequences. Generate command sequences against a simpler reference state machine, checking preconditions and observable state after each action rather than sharing the application's own transition code.
- **F07.14 — Controlled schedule generation**: Controlled schedule generation. Explore meaningful asynchronous interleavings with a scheduler, checking invariants after competing operations and shrinking failures into a reproducible sequence of observable events.
- **F07.15 — Differential oracles**: Differential oracles. Compare results with an independent implementation, trusted reference, or supported prior version, explicitly classifying expected differences and avoiding shared code that reproduces the same defect.
- **F07.16 — Parser structure limits**: Parser structure limits. Generate nested, recursive, truncated, and unusually long structured inputs, checking declared depth and size limits before expensive processing or unintended side effects occur.
- **F07.17 — Unicode adversaries**: Unicode adversaries. Exercise normalization variants, combining marks, bidirectional controls, unusual whitespace, and malformed encoding boundaries, verifying safe interpretation without collapsing legitimate distinct user inputs.
- **F07.18 — Numeric adversaries**: Numeric adversaries. Generate extreme magnitudes, fractional boundaries, non-finite values, and precision-sensitive combinations, checking rejection or declared arithmetic behavior before results enter persisted business state.
- **F07.19 — Temporal adversaries**: Temporal adversaries. Generate date ranges across timezone offsets, daylight-saving changes, leap dates, and invalid intervals, asserting the product's explicit calendar and elapsed-time semantics.
- **F07.20 — Protocol fuzzing**: Protocol fuzzing. Generate malformed or unusual headers, bodies, media types, and multipart boundaries against authorized test endpoints, checking bounded parsing and documented errors without unintended mutations.
- **F07.21 — Delivery permutations**: Delivery permutations. Generate duplicate, reordered, delayed, and interrupted event sequences, checking the application's documented convergence and idempotency properties under realistic platform delivery guarantees.
- **F07.22 — Schema evolution inputs**: Schema evolution inputs. Generate missing optional fields, unknown fields, new enum values, and supported legacy shapes, checking compatibility behavior against explicit version policies and F03 consumer obligations.
- **F07.23 — Relational fixture generation**: Relational fixture generation. Generate linked records with realistic cardinalities, orphan attempts, and competing updates, checking business invariants through the appropriate integration layer rather than assuming isolated objects suffice.
- **F07.24 — Actor-resource combinations**: Actor-resource combinations. Generate actor, tenant, resource, and operation combinations from the security policy model, checking isolation invariants while keeping the policy oracle independent of authorization implementation.
- **F07.25 — Constrained combinations**: Constrained combinations. Use pairwise or higher-order combination coverage for relevant flags, locales, roles, and environments, honoring impossible combinations and acknowledging that interaction sampling is not exhaustive coverage.
- **F07.26 — Bounded campaigns**: Bounded campaigns. Set runtime, memory, nesting, payload, and example-count limits for generated campaigns; report premature termination as incomplete and limit conclusions to inputs actually examined.
- **F07.27 — Realistic distributions**: Realistic distributions. Generate duplicate-heavy, sparse, skewed, and long-tail datasets that resemble meaningful workloads, checking behavior at problematic distributions instead of only uniformly random inputs.
- **F07.28 — Coverage-guided exploration**: Coverage-guided exploration. Apply coverage-guided fuzzing to suitable changed parsers and interpreters, tracking explored paths and replaying discovered minimal examples in the cheapest appropriate regression suite.
- **F07.29 — Hostile file corpora**: Hostile file corpora. Generate bounded corrupt, truncated, mislabeled, and expansion-heavy files for applicable import pipelines, verifying early rejection, controlled resource use, and understandable user-visible errors.
- **F07.30 — Curated regression corpus**: Curated regression corpus. Promote minimized real failures into a reviewed corpus, remove redundant examples carefully, and retain requirement-linked assertions so accumulated inputs continue to prove repaired behavior.

## Execution

Begin with critical existing behavior and the cheapest boundary that proves the invariant. Expand to runtime, browser, deployed, human, or deeper-audit evidence only when required. Missing dependencies or credentials are blocked evidence, never a pass.
