# F06 — Accessibility and usability

Load this guide when the application profile or changed risk selects this family. Record applicability, priority, cheapest convincing layer, execution tier, pass/fail criteria, owner, and evidence. Combine scenarios when one independent test proves several obligations; not-applicable requires a product-specific rationale.

- **F06.01 — Explicit accessibility target**: Explicit accessibility target. Establish the product's accessibility target, using WCAG 2.2 AA as a proposed default where appropriate, and map evidence to applicable criteria and user tasks.
- **F06.02 — Enforced automated findings**: Enforced automated findings. Integrate applicable automated accessibility checks with executable Storybook stories, configuring actionable violations to fail their required checks instead of leaving every finding advisory.
- **F06.03 — Keyboard completion**: Keyboard completion. Complete critical workflows using only the keyboard, verifying logical traversal, reachable actions, escape behavior, and the absence of traps across composed application screens.
- **F06.04 — Accessible control contracts**: Accessible control contracts. Verify exposed names, roles, states, and values for custom controls, including changes after interaction and associations that are missing despite visually persuasive labels.
- **F06.05 — Form comprehension**: Form comprehension. Check labels, required-field information, instructions, grouping, and error associations, ensuring users can understand what to enter without relying on placeholder text or position alone.
- **F06.06 — Focus transitions**: Focus transitions. Verify focus after route changes, dialog dismissal, validation failures, and content removal, ensuring the next useful interaction remains discoverable and does not unexpectedly reset.
- **F06.07 — Screen-reader verification**: Screen-reader verification. Manually exercise representative journeys with relevant screen-reader and browser combinations, recording meaningful reading, navigation, and announcement issues that automated checks cannot establish.
- **F06.08 — Dynamic announcements**: Dynamic announcements. Check live-region announcements for errors, progress, completion, and asynchronously added content, preventing silence, duplicated announcements, or interruptions that make the interface difficult to use.
- **F06.09 — Recoverable input errors**: Recoverable input errors. Verify error summaries navigate to affected fields, explain useful corrections, preserve entered data, and clear appropriately after recovery without leaving stale accessibility descriptions.
- **F06.10 — Target acquisition**: Target acquisition. Assess pointer target size, spacing, and precision demands against applicable criteria, including icon-only actions and densely packed controls on supported small screens.
- **F06.11 — Non-color meaning**: Non-color meaning. Verify charts, validation, selection, and status communicate essential meaning through text, shape, or pattern alongside color, including distinctions necessary to complete real tasks.
- **F06.12 — Contrast evidence**: Contrast evidence. Evaluate text and non-text contrast in relevant states and themes, using actual rendered foreground-background relationships and preserving exceptions only with documented applicability reasoning.
- **F06.13 — Responsive reading order**: Responsive reading order. Reuse F05 reflow evidence and manually verify semantic reading order, navigation order, and information continuity after resizing, zooming, or rearranging responsive regions.
- **F06.14 — Motion and interruption**: Motion and interruption. Assess animation, flashing, auto-updating content, and autoplay against applicable criteria, verifying available pause controls and supported motion preferences do not remove essential information.
- **F06.15 — Accessible media**: Accessible media. Test captions, transcripts, audio descriptions where needed, and media controls with representative content, checking accuracy, synchronization, discoverability, and keyboard operation.
- **F06.16 — Meaningful alternatives**: Meaningful alternatives. Review image alternatives in context, distinguishing decorative assets from informative diagrams and complex charts that need a useful text explanation beyond a short label.
- **F06.17 — Document structure**: Document structure. Verify headings, landmarks, lists, grouping, and reading sequence express the page's actual structure, allowing users to find and navigate meaningful sections efficiently.
- **F06.18 — Tables and grids**: Tables and grids. Check table headers, row-column relationships, captions, and grid navigation with assistive technology, particularly for selectable, editable, or virtualized data views.
- **F06.19 — Time-limited tasks**: Time-limited tasks. Exercise timeouts and expiring tasks with slower interaction, checking applicable warnings, extensions, saved progress, and recoverability without imposing avoidable data loss.
- **F06.20 — Accessible authentication**: Accessible authentication. Verify supported authentication permits password managers and paste, provides accessible alternatives to challenging interactions, and communicates recovery steps without exposing confidential account information.
- **F06.21 — Gesture alternatives**: Gesture alternatives. Complete dragging, swiping, multi-point, or motion-driven tasks through supported simpler alternatives, verifying the alternative produces the same meaningful outcome and remains discoverable.
- **F06.22 — Voice-control targeting**: Voice-control targeting. Test critical controls with relevant voice-control workflows, checking that visible labels align with accessible names and repeated labels remain distinguishable in context.
- **F06.23 — Language handling**: Language handling. Verify page and passage language, localized labels, and directional content are represented correctly for assistive technology, including mixed-language names and formatted values.
- **F06.24 — Accessible exports**: Accessible exports. Assess PDFs, emails, and exported documents for semantic structure, reading order, link names, and text alternatives alongside their visual checks in F05.
- **F06.25 — Hover and focus content**: Hover and focus content. Check tooltips and supplementary content for keyboard access, dismissal, persistence, and pointer reachability, avoiding content that disappears before the user can inspect it.
- **F06.26 — Availability semantics**: Availability semantics. Verify disabled, read-only, hidden, and unavailable controls expose appropriate semantics and explanations, preventing inaccessible controls from remaining unexpectedly focusable or appearing actionable.
- **F06.27 — Observed task success**: Observed task success. Run focused usability sessions with representative users, including people using relevant accessibility adaptations, recording task completion, errors, confusion, and recovery without coaching away problems.
- **F06.28 — Consequential-action understanding**: Consequential-action understanding. Observe users completing consequential workflows, checking that labels, summaries, confirmations, and recovery communicate the actual outcome before users commit an irreversible action.
- **F06.29 — Perceived responsiveness**: Perceived responsiveness. Evaluate whether loading and long-running operations provide understandable feedback, progress, and cancellation where supported, especially when users cannot visually monitor subtle interface changes.
- **F06.30 — First-use discoverability**: First-use discoverability. Evaluate empty states and progressive disclosure with unfamiliar participants, checking whether they can identify the next valid action and complete the intended task without explanation.

## Execution

Begin with critical existing behavior and the cheapest boundary that proves the invariant. Expand to runtime, browser, deployed, human, or deeper-audit evidence only when required. Missing dependencies or credentials are blocked evidence, never a pass.
