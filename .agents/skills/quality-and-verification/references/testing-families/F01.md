# F01 — Unit and business behavior

Load this guide when the application profile or changed risk selects this family. Record applicability, priority, cheapest convincing layer, execution tier, pass/fail criteria, owner, and evidence. Combine scenarios when one independent test proves several obligations; not-applicable requires a product-specific rationale.

- **F01.01 — Independent examples**: Independent examples. Translate business rules into explicit input/output examples with independently calculated expectations, including rejected cases; identify the requirement each example proves before implementing behavior.
- **F01.02 — Legacy characterization**: Legacy characterization. Characterize correct behavior in critical existing paths before changing them; distinguish accepted compatibility requirements from known defects that require a new failing regression.
- **F01.03 — Minimal defect reproductions**: Minimal defect reproductions. Reduce each discovered business defect to its smallest public-interface reproducer, observe the intended failure, and retain the test after the repair.
- **F01.04 — Equivalence classes**: Equivalence classes. Build readable tables for meaningful input classes, such as eligible, ineligible, exceptional, and grandfathered customers, with descriptive case names exposing policy differences.
- **F01.05 — Boundary neighborhoods**: Boundary neighborhoods. Exercise values immediately below, at, and above thresholds, plus absent, null, empty, zero, and negative inputs whenever those meanings differ.
- **F01.06 — Monetary representation**: Monetary representation. Verify monetary calculations using the application's declared precision and supported currency scales; reject accidental floating-point drift or unsupported fractional amounts at domain boundaries.
- **F01.07 — Rounding and allocation**: Rounding and allocation. Test rounding direction, discount order, tax order, and remainder allocation with independently worked examples whose line items reconcile to the declared total.
- **F01.08 — Rule precedence**: Rule precedence. Exercise overlapping business rules deliberately, proving which restriction, entitlement, discount, or exception wins and how conflicting configuration produces an understandable result.
- **F01.09 — Expiration edges**: Expiration edges. Inject a controllable clock to test just-before, exact-boundary, and just-after expiry behavior for tokens, reservations, quotes, trials, and domain deadlines.
- **F01.10 — Calendar semantics**: Calendar semantics. Separate calendar-day rules from elapsed-duration rules; test daylight-saving transitions, leap days, month ends, and inclusive versus exclusive boundaries for applicable business dates.
- **F01.11 — Randomness and identifiers**: Randomness and identifiers. Inject randomness and identifier generation so tests reproduce collisions, retry limits, and selection decisions without depending on particular production-generated identifiers.
- **F01.12 — Text normalization**: Text normalization. Specify whitespace, Unicode normalization, case sensitivity, and empty-string handling for names and identifiers; verify normalization never merges distinct values unintentionally.
- **F01.13 — Representation semantics**: Representation semantics. Test serialization and deserialization examples for absent fields, explicit nulls, defaults, and legacy values; preserve distinctions that callers or persisted records rely on.
- **F01.14 — State transitions**: State transitions. Enumerate valid and invalid transitions for critical domain state machines, asserting resulting state and rejected side effects through their public operations.
- **F01.15 — Repeated commands**: Repeated commands. Verify repeated command decisions respect the domain's idempotency rules, including repeated cancellations, approvals, and completion events with different legitimate request identifiers.
- **F01.16 — Mutation boundaries**: Mutation boundaries. Check that domain operations preserve caller-owned inputs and unrelated state where promised, including nested references whose accidental mutation can corrupt later decisions.
- **F01.17 — Domain error contracts**: Domain error contracts. Assert stable error categories, machine-readable codes, and recovery information; avoid coupling tests to incidental wording unless that wording is a contractual requirement.
- **F01.18 — Validation diagnostics**: Validation diagnostics. Verify validation identifies the correct fields and actionable reasons, preserves acceptable values, and reports multiple independent problems according to the documented validation policy.
- **F01.19 — Asynchronous completion**: Asynchronous completion. Exercise successful resolution, rejection, and cancellation of asynchronous domain operations, asserting settled results and preventing unobserved promise failures from disappearing after test completion.
- **F01.20 — In-process races**: In-process races. Use controlled scheduling to exercise competing calls to shared in-process state, proving deduplication, single-flight behavior, or documented conflict handling without timing guesses.
- **F01.21 — Resource lifecycle**: Resource lifecycle. Verify ownership and release of resources acquired by domain adapters, including cancellation and exceptional exits; assert meaningful resource availability rather than private cleanup implementation details.
- **F01.22 — Cache decisions**: Cache decisions. Unit-test cache eligibility, key partitioning, expiry decisions, and invalidation rules with deterministic inputs; use F03 integration scenarios to prove actual cache wiring.
- **F01.23 — Ordering and pagination**: Ordering and pagination. Test stable tie breakers, cursor boundaries, empty pages, and insertion between pages against the declared ordering contract, preventing missing or duplicated business records.
- **F01.24 — Aggregation arithmetic**: Aggregation arithmetic. Verify empty aggregates, weighted calculations, excluded records, denominator-zero behavior, and reconciliation using small datasets whose expected results can be checked independently.
- **F01.25 — Numeric validity**: Numeric validity. Exercise NaN, infinity, unsafe integers, overflow-prone conversions, and negative zero where relevant; ensure numeric validation fails before values contaminate downstream business calculations.
- **F01.26 — Configuration semantics**: Configuration semantics. Test meaningful policy branches, missing settings, and explicit overrides, including the difference between an unset option and a deliberately disabled option.
- **F01.27 — Units and dimensions**: Units and dimensions. Verify conversion factors, dimensional consistency, signs, and rounding for sizes, durations, rates, and quantities; reject incompatible units before combining their values.
- **F01.28 — Useful dependency fakes**: Useful dependency fakes. Model external dependency responses only at genuine seams; assert externally meaningful outcomes so internal refactoring does not require rewriting otherwise valid behavior tests.
- **F01.29 — Value-object identity**: Value-object identity. Test equality, canonical identity, and duplicate recognition for domain value objects, including superficially similar inputs that must remain distinct under business rules.
- **F01.30 — Partial updates**: Partial updates. Verify patches distinguish omitted fields, explicit clearing, and replacement values; ensure nested updates preserve unrelated properties and enforce invariants across the resulting object.

## Execution

Begin with critical existing behavior and the cheapest boundary that proves the invariant. Expand to runtime, browser, deployed, human, or deeper-audit evidence only when required. Missing dependencies or credentials are blocked evidence, never a pass.
