# F05 — Visual regression and compatibility

Load this guide when the application profile or changed risk selects this family. Record applicability, priority, cheapest convincing layer, execution tier, pass/fail criteria, owner, and evidence. Combine scenarios when one independent test proves several obligations; not-applicable requires a product-specific rationale.

- **F05.01 — Stable baseline environments**: Stable baseline environments. Establish visual baselines with explicit browser, operating system, fonts, theme, and rendering settings, recording those inputs so environmental differences are not mistaken for product changes.
- **F05.02 — Shared-theme impact**: Shared-theme impact. Select representative consuming stories and pages for theme.tools and ui.theme.tools changes, covering affected tokens and primitives instead of assuming the shared package's own gallery proves consumer compatibility.
- **F05.03 — High-value visual assertions**: High-value visual assertions. Capture critical layouts and reusable patterns with reviewable screenshots, choosing regions where clipping, overlap, hierarchy, or misplaced controls would cause meaningful user harm.
- **F05.04 — State-specific appearance**: State-specific appearance. Compare relevant loading, empty, error, selected, expanded, and pending appearances using F02 stories, reusing their setup instead of creating a second contradictory state model.
- **F05.05 — Breakpoint boundaries**: Breakpoint boundaries. Inspect representative widths immediately around real responsive breakpoints, including narrow supported screens, to detect controls disappearing or overflowing during layout transitions.
- **F05.06 — Container-driven layout**: Container-driven layout. Test reusable widgets inside constrained and nested containers, verifying responsive behavior depends correctly on available space rather than only the top-level browser viewport.
- **F05.07 — Font failure and substitution**: Font failure and substitution. Exercise unavailable fonts, delayed loading, fallback glyphs, and supported font substitution, checking that essential text and controls remain legible and usable.
- **F05.08 — International text layout**: International text layout. Render long translations, right-to-left text, mixed scripts, combining marks, and representative CJK content, inspecting truncation, alignment, punctuation, and reading-order defects.
- **F05.09 — Zoom and reflow**: Zoom and reflow. Inspect supported zoom and text-resize conditions on critical pages, checking reflow, fixed overlays, sticky controls, and continued access to essential information.
- **F05.10 — Forced colors**: Forced colors. Exercise supported system forced-color modes and inspect icons, borders, focus indicators, and selected states, ensuring custom styling does not erase their visual distinctions.
- **F05.11 — Reduced motion**: Reduced motion. Capture reduced-motion states and transition endpoints, checking that necessary feedback remains visible and content does not depend on an animation completing successfully.
- **F05.12 — Theme transitions**: Theme transitions. Compare supported light, dark, and system-driven themes, including a live preference change, verifying surfaces, assets, and embedded components adopt the intended appearance together.
- **F05.13 — Extreme content shapes**: Extreme content shapes. Use unusually long names, large totals, dense charts, empty labels, and maximal supported item counts to detect layout failures hidden by attractive demonstration data.
- **F05.14 — Minimal screenshot masking**: Minimal screenshot masking. Mask only genuinely nondeterministic regions and document why, preserving assertions for their presence and dimensions so masking cannot conceal meaningful visual regressions.
- **F05.15 — Capture readiness**: Capture readiness. Wait for intended fonts, images, layout, and application state before capture; control time and animation deliberately without hiding unsettled or broken production behavior.
- **F05.16 — Reviewed baseline changes**: Reviewed baseline changes. Review image diffs against the intended design change, investigate unexplained regions, and record the acceptance reason before replacing baselines or relaxing comparison thresholds.
- **F05.17 — Real engine coverage**: Real engine coverage. Use separate supported runners for Firefox and WebKit obligations when needed; Cloudflare Browser Run's remote Chromium coverage does not establish compatibility with other engines.
- **F05.18 — Actual mobile platforms**: Actual mobile platforms. Supplement browser emulation with representative real devices for platform-sensitive behavior, including virtual keyboards, safe areas, orientation changes, and mobile browser chrome.
- **F05.19 — Operating-system differences**: Operating-system differences. Test supported desktop platforms where native controls, fonts, shortcuts, or scrollbars matter, maintaining justified environment-specific expectations instead of forcing one platform's pixels everywhere.
- **F05.20 — Pixel density and scaling**: Pixel density and scaling. Inspect relevant device-pixel ratios and operating-system scaling levels, detecting blurry assets, clipped canvas content, and dimensions that accidentally mix device and CSS pixels.
- **F05.21 — CSS feature fallbacks**: CSS feature fallbacks. Exercise supported environments lacking optional CSS capabilities, confirming feature detection and fallbacks preserve meaningful layout and interaction rather than silently removing essential content.
- **F05.22 — Print layout**: Print layout. Inspect printed critical documents for page breaks, repeated headers, hidden navigation, clipped tables, and readable contrast using realistic multi-page content and supported paper sizes.
- **F05.23 — Export rendering**: Export rendering. Render generated PDFs or images and compare critical visual regions alongside content assertions, catching missing glyphs, broken charts, and renderer-specific pagination errors.
- **F05.24 — Image and icon assets**: Image and icon assets. Verify responsive image selection, intrinsic sizing, aspect ratios, transparency, and icon alignment, including failure placeholders when a meaningful image cannot load.
- **F05.25 — Resource-policy failures**: Resource-policy failures. Exercise blocked or failed styles, fonts, images, and embedded resources under representative policies, checking the resulting page communicates failures and retains usable critical controls.
- **F05.26 — Layering conflicts**: Layering conflicts. Inspect dialogs, tooltips, dropdowns, sticky headers, and banners together, including scrolling, to detect stacking-context conflicts that isolate otherwise correctly rendered components.
- **F05.27 — Long-page scrolling**: Long-page scrolling. Inspect long content with nested scroll regions and sticky elements, verifying anchored navigation, scroll restoration, and access to final actions at supported dimensions.
- **F05.28 — Interaction-state visibility**: Interaction-state visibility. Compare hover, focus, active, selected, invalid, and disabled appearances for critical controls, linking evidence to F06 criteria without duplicating the interaction scenario.
- **F05.29 — Embedded compatibility**: Embedded compatibility. Test important third-party embeds or application widgets inside their actual host contexts, checking sizing, theme boundaries, clipping, and loading failures across supported embedding configurations.
- **F05.30 — User browser adaptations**: User browser adaptations. Check autofill, password managers, browser translation, and relevant reading settings on critical pages, documenting incompatibilities that clean automated browser profiles do not represent.

## Execution

Begin with critical existing behavior and the cheapest boundary that proves the invariant. Expand to runtime, browser, deployed, human, or deeper-audit evidence only when required. Missing dependencies or credentials are blocked evidence, never a pass.
