# F04 — System and end-to-end journeys

Load this guide when the application profile or changed risk selects this family. Record applicability, priority, cheapest convincing layer, execution tier, pass/fail criteria, owner, and evidence. Combine scenarios when one independent test proves several obligations; not-applicable requires a product-specific rationale.

- **F04.01 — Existing critical journeys**: Existing critical journeys. Inventory critical existing journeys by user harm and business impact, then establish trustworthy coverage for their current behavior before expanding to peripheral screens.
- **F04.02 — Persisted business outcomes**: Persisted business outcomes. Finish each critical journey by checking the meaningful persisted result, such as a saved order or granted membership, instead of treating a success toast as sufficient evidence.
- **F04.03 — First-use completion**: First-use completion. Exercise first-use account creation and required onboarding through the real system, proving a new eligible user can reach their first meaningful successful task.
- **F04.04 — Tenant switching**: Tenant switching. Switch between tenants with distinguishable records and verify navigation, cached views, drafts, and subsequent operations consistently reflect the selected tenant throughout a complete journey.
- **F04.05 — Representative actor journeys**: Representative actor journeys. Execute critical workflows as representative authorized roles, verifying expected action availability and completed outcomes while security tests cover the exhaustive permission matrix.
- **F04.06 — Resource lifecycle**: Resource lifecycle. Exercise meaningful create, edit, archive, and restore flows across navigation and reload, verifying visible state and persisted records agree at each lifecycle boundary.
- **F04.07 — Payment lifecycle**: Payment lifecycle. Where applicable, exercise checkout, asynchronous payment confirmation, and refund outcomes with authorized sandbox instruments, reconciling application state, receipts, and provider events.
- **F04.08 — Entitlement changes**: Entitlement changes. Exercise supported plan and seat changes in a test environment, verifying entitlement updates reach existing sessions and affected workflows at the documented time.
- **F04.09 — External connection lifecycle**: External connection lifecycle. Complete critical integration setup, successful use, revoked access, and reconnection, verifying the user receives accurate status and can recover without corrupting existing application data.
- **F04.10 — Authenticated deep links**: Authenticated deep links. Open protected deep links from a fresh session, complete authentication, and verify the intended destination and permitted operation survive redirects and intermediate onboarding requirements.
- **F04.11 — Session expiry during work**: Session expiry during work. Expire a session during a critical task and verify the documented recovery preserves appropriate input, requires authentication, and avoids accidentally repeating committed operations.
- **F04.12 — Refresh and draft recovery**: Refresh and draft recovery. Reload or reopen supported draft workflows after meaningful intermediate steps, verifying the user sees the correct saved progress and understandable information about unsaved changes.
- **F04.13 — Connectivity recovery**: Connectivity recovery. Interrupt connectivity during selected critical interactions and verify offline feedback, recovery, and reconciliation, including cases where the server committed work before the client lost its response.
- **F04.14 — Dependency outages**: Dependency outages. Make a critical upstream dependency unavailable in an isolated environment and verify the full user journey exposes accurate failure, useful recovery, and no misleading completion state.
- **F04.15 — Duplicate submission**: Duplicate submission. Repeat submissions through rapid activation and response loss, proving the complete system creates only the intended logical operation under its declared idempotency policy.
- **F04.16 — Concurrent editing**: Concurrent editing. Have two isolated users edit the same resource and verify conflict detection, permitted merging, or last-writer behavior matches the product's explicit collaboration contract.
- **F04.17 — Locale-sensitive journeys**: Locale-sensitive journeys. Complete date, currency, and quantity workflows using representative supported locales and timezones, verifying displayed values are interpreted and persisted consistently across the journey.
- **F04.18 — File journeys**: File journeys. Upload, process, and download representative files through the complete application, checking content integrity, ownership, filenames, and usable failure handling for interrupted transfers.
- **F04.19 — Multi-step cancellation**: Multi-step cancellation. Cancel and resume supported multi-step workflows at consequential boundaries, verifying temporary resources, retained progress, and eventual completion remain understandable and internally consistent.
- **F04.20 — Email-linked actions**: Email-linked actions. Follow actual invitation or recovery links delivered to controlled test inboxes, exercising valid, expired, and already-used links through their complete user-visible outcomes.
- **F04.21 — Background-job completion**: Background-job completion. Start a critical background job through the interface and observe its actual completion or failure, checking progress, final results, and subsequent access to produced resources.
- **F04.22 — Observable synchronization**: Observable synchronization. Wait for meaningful system conditions with bounded polling or event signals, so asynchronous journey tests expose genuine delays and failures without relying on arbitrary sleeps.
- **F04.23 — Real external seams**: Real external seams. Keep a small authorized sandbox journey for critical external providers, verifying credentials, routing, and callbacks that deterministic local stubs cannot establish.
- **F04.24 — Feature rollout journeys**: Feature rollout journeys. Exercise risk-relevant flag combinations using explicit assignments, including transitions during existing sessions where supported, and preserve the assignments alongside the resulting journey evidence.
- **F04.25 — Browser history**: Browser history. Use back, forward, refresh, and direct navigation around important mutations, verifying history restores appropriate state and never silently resubmits a consequential operation.
- **F04.26 — Search-to-export consistency**: Search-to-export consistency. Apply filters, ordering, and pagination to known records, then export or act on the results, proving the selected dataset matches the user's visible scope.
- **F04.27 — Multiple-tab behavior**: Multiple-tab behavior. Change critical state in another tab and verify stale views reconcile according to product expectations, especially sign-out, tenant changes, and already-completed actions.
- **F04.28 — Browser capability failures**: Browser capability failures. Deny required browser permissions or disable an optional capability during a journey, verifying the application offers an accurate fallback and preserves already completed work.
- **F04.29 — Upgrade continuity**: Upgrade continuity. Start from representative prior-release records and saved links, then complete the current application's critical journeys, detecting migration and interpretation defects missed by fresh-only fixtures.
- **F04.30 — Mixed batch outcomes**: Mixed batch outcomes. For batch workflows, mix successful, rejected, and cancelled items and verify item-level results, retries, totals, and completion notifications agree throughout the complete system.

## Execution

Begin with critical existing behavior and the cheapest boundary that proves the invariant. Expand to runtime, browser, deployed, human, or deeper-audit evidence only when required. Missing dependencies or credentials are blocked evidence, never a pass.
