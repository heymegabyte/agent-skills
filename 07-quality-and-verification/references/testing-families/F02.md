# F02 — Components and interactions

Load this guide when the application profile or changed risk selects this family. Record applicability, priority, cheapest convincing layer, execution tier, pass/fail criteria, owner, and evidence. Combine scenarios when one independent test proves several obligations; not-applicable requires a product-specific rationale.

- **F02.01 — Critical component stories**: Critical component stories. Establish stories for components on critical existing journeys first, rendering their real exported interfaces with representative data and the providers production behavior requires.
- **F02.02 — Independent story fixtures**: Independent story fixtures. Give each story a minimal explicit fixture and resettable dependencies so interaction results cannot depend on another story's mutations, execution order, or lingering browser state.
- **F02.03 — Meaningful state matrices**: Meaningful state matrices. Cover loaded, loading, empty, error, disabled, and pending states only where meaningful; assert available actions and recovery behavior for each state.
- **F02.04 — User-facing interaction assertions**: User-facing interaction assertions. Write story play functions using roles, labels, and visible outcomes; reserve implementation-specific selectors for cases where a stable semantic interface cannot express the interaction.
- **F02.05 — Form timing**: Form timing. Exercise validation during editing, blur, and submission, verifying when messages appear, when submission becomes available, and whether valid user input survives errors.
- **F02.06 — Keyboard behavior**: Keyboard behavior. Test expected keyboard operations for menus, comboboxes, tabs, and composite controls; connect these behavior checks to the broader accessibility obligations in F06.
- **F02.07 — Pointer interactions**: Pointer interactions. Exercise click, pointer cancellation, touch activation, and outside dismissal where supported, including movement that should cancel an activation rather than trigger an unintended action.
- **F02.08 — Controlled and uncontrolled state**: Controlled and uncontrolled state. Verify supported controlled and uncontrolled modes, prop changes after mounting, and reset behavior without assuming the initial render represents the component's entire lifecycle.
- **F02.09 — Stale asynchronous responses**: Stale asynchronous responses. Resolve competing requests in reverse order and verify the component retains the newest valid result, including when the user changes filters or identity.
- **F02.10 — Optimistic updates**: Optimistic updates. Test optimistic success, rollback, partial rejection, and retry, checking that displayed values, pending indicators, and accessible feedback remain consistent with the accepted operation.
- **F02.11 — Overlay coordination**: Overlay coordination. Exercise nested dialogs, popovers, and menus through open, close, escape, and outside interaction, verifying dismissal order and focus restoration to the appropriate initiating control.
- **F02.12 — Unmount cleanup**: Unmount cleanup. Unmount during requests, subscriptions, and timers; assert that obsolete work stops affecting the interface and remounting does not duplicate visible updates or event handling.
- **F02.13 — Repeated activation**: Repeated activation. Rapidly activate submission and destructive-action controls to verify pending-state behavior and one intended logical action, without relying exclusively on a disabled-button snapshot.
- **F02.14 — Debounce and throttle**: Debounce and throttle. Advance a controlled clock across debounce and throttle boundaries, checking the final submitted value, cancellation, and immediate actions that must bypass delayed processing.
- **F02.15 — Router synchronization**: Router synchronization. Test component state against route parameters and query changes, including browser-originated navigation, invalid values, and the documented default when a parameter disappears.
- **F02.16 — Selection models**: Selection models. Exercise single selection, range selection, select-all, filtering, and disabled items where supported; verify displayed counts and emitted selections describe the same eligible records.
- **F02.17 — Identity-dependent rendering**: Identity-dependent rendering. Change tenant, actor, or entitlement providers after mounting and verify controls refresh appropriately; let security-family tests separately prove server-side authorization enforcement.
- **F02.18 — Shared UI contracts**: Shared UI contracts. Exercise theme.tools public exports through representative consuming components and check contracts documented in ui.theme.tools, detecting incompatible props, provider assumptions, or events before consumers ship.
- **F02.19 — Theme behavior**: Theme behavior. Switch supported theme and motion preferences during interaction, verifying control state, visibility, and action availability survive the change; place appearance comparisons in F05.
- **F02.20 — Composition contracts**: Composition contracts. Test documented slots, children, refs, and wrapper composition, especially where consumers replace triggers or content while relying on focus management and event delivery.
- **F02.21 — Event propagation**: Event propagation. Exercise nested clickable elements and delegated events, verifying intended parent behavior, prevented defaults, and propagation boundaries without exposing private handler sequencing as the contract.
- **F02.22 — Reordering controls**: Reordering controls. Test supported drag-and-drop transitions, cancellation, invalid targets, and keyboard alternatives; assert final item order and emitted changes rather than intermediate implementation coordinates.
- **F02.23 — Virtualized collections**: Virtualized collections. Scroll beyond initially rendered rows and verify selection, editing, focus, and identity remain attached to the correct records as DOM elements are recycled.
- **F02.24 — Responsive behavior**: Responsive behavior. Change viewport or container dimensions across meaningful layout transitions, checking navigation, overflow actions, and preserved interaction state when controls move or collapse.
- **F02.25 — Localization updates**: Localization updates. Change locale after mounting and verify messages, formatting, validation text, and fallback translations update together, including components retaining previously entered user values.
- **F02.26 — Hydration correctness**: Hydration correctness. For server-rendered interfaces, test hydration with real initial data and browser state, detecting lost input, duplicated actions, or divergent controls during client takeover.
- **F02.27 — Upload interfaces**: Upload interfaces. Exercise file selection, validation, progress, cancellation, and retry with controlled transport responses; verify accessible status and the distinction between completed and partially accepted files.
- **F02.28 — Browser permission outcomes**: Browser permission outcomes. Test components using clipboard, media, notifications, or downloads against granted, denied, unavailable, and cancelled outcomes, ensuring actionable fallbacks without misreporting success.
- **F02.29 — Live update presentation**: Live update presentation. Feed subscription components connection loss, recovery, duplicate updates, and out-of-order updates, verifying visible reconciliation and preserving the user's in-progress local interaction.
- **F02.30 — Executable Storybook coverage**: Executable Storybook coverage. Run suitable stories and their assertions through Storybook addon-vitest with supported project configuration, mapping stories to source components and shared packages for impacted selection.

## Execution

Begin with critical existing behavior and the cheapest boundary that proves the invariant. Expand to runtime, browser, deployed, human, or deeper-audit evidence only when required. Missing dependencies or credentials are blocked evidence, never a pass.
