# Cross-service & standards — service-idea catalog (X-01…30)

30 reusable cross-cutting improvement HYPOTHESES absorbed from REVISION-2 Appendix D7 (research date 2026-10-28). These span Sentry + Langfuse + PostHog + GA4 + GTM + Promptfoo + the standards layer (OTel, W3C Trace Context, OpenFeature, OpenAPI, restic/rclone). Reusable METHODS to assess against each project's real evidence — NOT claims about any account, NOT live product state (§23.9 / §19.3). Pointed to by `rules/observability-ops-supervisor.md`.

## Global constraints (apply to every X idea)

- A correlation ID / analytics group / shared trace is ATTRIBUTION, never authorization; enforce authz + destination routing independently. Attribution reports ≠ accounting; reconcile money to the provider-confirmed authority.
- **Customer-analytics tenant boundary (loop invariant):** owner tags/containers never on customer-generated sites by default; tenant containers never execute in the shared editor/admin. No creds / personal payloads in trace propagation.
- Correlation is a hypothesis, not cause; a merge / generated schema ≠ a deployed compatible provider; a green check / passing assertion ≠ the real outcome. Eval providers/callbacks execute code — isolate them.

## Ideas

- **X-01** — One versioned event contract *(measurement quality)*: canonical business events + destination-specific adapters + documented transforms. *Verify:* representative events end-to-end; detect schema drift + dups WITHOUT requiring equal counts across consent/attribution models. Constraint: separate product facts from vendor conventions; preserve tenant destinations. Src: json-schema, datalayer.
- **X-02** — Follow a job across the whole system *(observability)*: propagate W3C trace context + explicit task/run correlation into OTel/Sentry/Langfuse records. *Verify:* reconstruct a controlled async job with logical work + real provider calls + retries + distinguishable duplicate instrumentation; idempotency checked separately vs the durable ledger. Constraint: span links for async fan-out; no creds/personal payloads in propagation. Src: w3.org/trace-context, otel/traces.
- **X-03** — Tenant-scoped attribution map *(privacy/tenancy)*: an authorized pseudonymous mapping linking permitted product outcomes with operational evidence WITHIN one tenant. *Verify:* tenant switching + deletion fixtures → correct attribution, no cross-tenant visibility. Constraint: a correlation ID / analytics group ≠ authorization. Src: posthog group-analytics, privacy.
- **X-04** — Release evidence dossier *(release quality)*: attach release SHA + contract version + flag state + Sentry health + eval scores + cohorts to each important release. *Verify:* a reviewer can identify which code/prompt/config/cohort produced an observed regression. Constraint: account for staggered deploy + delayed analytics + sampling + concurrent changes; correlation alone is insufficient. Src: langfuse evaluation/overview, openfeature tracking.
- **X-05** — Decision freshness gate *(decision quality)*: require explicit freshness/confidence criteria before a metric can drive a change. *Verify:* a delayed/incomplete source → an unknown/deferred decision while independent urgent-incident evidence stays actionable. Constraint: GA4 / pipelines / traces have different clocks; a cached empty ≠ healthy. Src: analytics/11198161, posthog api/queries.
- **X-06** — Reconcile outcomes to their authority *(revenue integrity)*: reconcile user-facing success + conversions vs provider-confirmed outcomes; flag missing/duplicated measurement. *Verify:* controlled payment/refund/publication match the authoritative records with explained analytics discrepancies. Constraint: attribution ≠ accounting; no revenue inferred from a client success-click. Src: ga4/ecommerce, posthog api/queries.
- **X-07** — Rehearse the complete incident-recovery loop *(operational readiness)*: an isolated fault-injection drill through telemetry intake → triage → ownership → remediation → verify; compare vs independent ground truth. *Verify:* the intended incident → one owned task + protected work stays scheduled + recovery evidence + no premature-success/uncontrolled-retry. Constraint: isolated or an authorized drill; a retained prompt fixture ≠ the full pipeline proven. Src: toxiproxy, queues/delivery-guarantees, promptfoo/tracing.
- **X-08** — Evaluation-gated feature rollout *(experimentation)*: require relevant offline checks before a bounded flag rollout, observe real outcomes before expansion. *Verify:* an injected regression blocks promotion; a reversible rollout is halted with evidence + recorded ownership. Constraint: flags ≠ entitlement; auto-rollback needs predefined authority + comparable data. Src: openfeature intro, promptfoo ci-cd.
- **X-09** — One support evidence packet *(support)*: assemble a minimal tenant-scoped diagnostic packet (consented replay/error/trace/product-event) → one owned task. *Verify:* a representative case has enough to reproduce or explicitly identify missing context, no unrelated sessions. Constraint: no auto-message customers / full recordings / PII in public issues. Src: posthog replay/privacy, otel/traces.
- **X-10** — Measure successful journeys not availability alone *(reliability/UX)*: journey-specific SLIs (successful site publication / inbox delivery completion). *Verify:* a healthy HTTP response + a failed downstream op → detected as a journey failure. Constraint: keep synthetic distinguishable from customer analytics; respect provider test limits. Src: browser-run/cdp/playwright, otel/semconv.
- **X-11** — Cost per successful customer outcome *(economics)*: cost for useful outcomes by route/workflow/cohort; propose cheaper impls preserving quality. *Verify:* a candidate reduces cost-per-accepted-outcome without violating quality/latency gates. Constraint: state incomplete cost coverage; don't multiply sampled usage into a precise fleet bill. Src: langfuse token-and-cost, promptfoo expected-outputs.
- **X-12** — Portfolio idea prioritization from evidence *(strategy)*: rank ready work by benefit/confidence/effort/reversibility/dependency. *Verify:* a review can explain why selected work outranks alternatives + mandatory incidents retain capacity. Constraint: scores = planning estimates not measured ROI; prevent duplicated signals boosting rank. Src: spec-kit agentic-assessment, openspec concepts.
- **X-13** — Plugin installation health funnel *(extension ecosystem)*: instrument discovery → authorize → install → first-use → failure → removal with versioned events + trace links. *Verify:* a canary extension followed listing → first-value; failed install phases identify actionable causes. Constraint: tenant permissions/creds stay outside public catalog metadata. Src: backstage architecture, workers-for-platforms.
- **X-14** — Per-extension reliability + resource accountability *(extension ops)*: scoped health + budget summaries; contain an unhealthy extension via approved controls. *Verify:* an over-budget test extension is limited without affecting another tenant's install. Constraint: CF custom CPU/subrequest limits are per-invocation; aggregate spend needs a separate ledger; isolation ≠ capability authz. Src: workers-for-platforms custom-limits, worker-isolation.
- **X-15** — Rehearse feature-flag provider compatibility *(portability)*: replay approved contexts vs old + proposed providers in a shadow harness, compare decisions/errors without duplicating live exposure. *Verify:* supported cases preserve assignment/fallback; deviations explicit; a canary returns to the original without corrupting history. Constraint: OpenFeature standardizes an interface, not targeting/rules-export; don't add a flag service just to test. Src: openfeature intro, posthog openfeature-js, tracking.
- **X-16** — Cross-repository compatibility gate *(interoperability)*: block incompatible rollout sequences; link provider/consumer OpenSpec changes to one objective. *Verify:* representative old clients work vs the new provider before consumer migration is declared complete. Constraint: a merge / generated schema ≠ the compatible provider deployed. Src: openapi spec, pact.
- **X-17** — Deletion + retention reconciliation *(data lifecycle)*: coordinate supported deletion/redaction/retention; record scoped evidence of what remains. *Verify:* a controlled request verified after the documented async period across stores + separately-copied datasets, explicit exceptions, no silent reintroduction on restore. Constraint: restricted API history ≠ older records absent; account for backups/aggregates/copies. Src: posthog privacy, langfuse data-deletion.
- **X-18** — Coordinated replay collection *(privacy/cost)*: a deliberate per-surface collection responsibility to avoid duplicate recordings. *Verify:* incident investigations keep useful evidence while recorded volume + sensitive-field exposure stay within policy. Constraint: a shared correlation key ≠ authorize replay transfer; preserve each tool's masking. Src: posthog replay/privacy, sentry session-replay.
- **X-19** — Telemetry overload control *(reliability/economics)*: bound buffering + volume + sampling/redaction, preserve critical failure evidence. *Verify:* a simulated outage/burst doesn't exhaust memory or stall core ops; loss stays visible. Constraint: don't sample away the only audit evidence or misrepresent sampled rates. Src: otel collector/resiliency, workers/opentelemetry-export.
- **X-20** — Detect the absence of observability *(monitoring quality)*: validate payload schemas, then send small labeled canary events through the real configured path + read back arrival. *Verify:* breaking one integration → a telemetry-health incident after its freshness window, not a falsely-green dashboard. Constraint: GA4 debug validation doesn't ingest into reports or validate all creds; exclude canaries from business metrics. Src: otel internal-telemetry, ga4 validating-events.
- **X-21** — End-to-end content-publication evidence *(content ops)*: track content-task → AI-gen/eval → render → upload-session → remote-ID → engagement. *Verify:* an interrupted upload resumes/reconciles without blind duplication; the published URL maps to its generation/evidence record. Constraint: quality + rights checks precede publication; delayed engagement ≠ a failed upload. Src: youtube resumable-upload, langfuse observability.
- **X-22** — Tenant-owned analytics onboarding *(customer platform)*: a guided validation of a customer's analytics setup using THEIR authorized destinations. *Verify:* two tenants configure/test/change/remove analytics without events or executable containers crossing sites. Constraint: never mount tenant containers in the shared editor/admin; owner IDs excluded from generated sites by default. Src: gtm api/v2, posthog api.
- **X-23** — Recovery preserves task + measurement integrity *(recovery)*: restore a worker/control-plane slice with its durable state + reconcile external outcomes before resuming. *Verify:* a restore exercise recovers agreed data + resumes work without blind republishing or resetting overdue obligations. Constraint: backups application-consistent; historical events need explicit dedupe/replay semantics. Src: restic restore, rclone check.
- **X-24** — Synthetic + real-user evidence together *(UX verification)*: controlled browser journeys to investigate observed friction, then measure whether the released fix improves the corresponding real outcome. *Verify:* the synthetic case reproduces + verifies the defect; a suitable real cohort confirms/rejects the hypothesis. Constraint: automation ≠ every a11y/usability outcome; avoid contaminating prod funnels. Src: browser-run/cdp/playwright, posthog funnels.
- **X-25** — Evidence-backed operating digest *(operations)*: a concise owner digest with coverage-debt / incidents / evaluated-ideas / deployed-fixes / measured-results / source-freshness + links + unresolved questions + next action. *Verify:* every factual claim traces to current evidence; researched/planned stays distinct from deployed/measured. Constraint: use the authorized reporting destination; don't broadcast customer/incident details. Src: openspec commands, otel observability-primer.
- **X-26** — Experiment readout with operational guardrails *(product experimentation)*: predefine unit / hypothesis / primary-outcome / safety-metrics / window; review product + operational effects together. *Verify:* the readout reports assignment quality + uncertainty + sample limits + guardrail breaches before a promotion decision. Constraint: no causation from an uncontrolled before/after or incompatible attribution denominators. Src: posthog experiments, openfeature tracking.
- **X-27** — Upstream changes → scoped migration work *(maintenance)*: map relevant removals/capability-changes to affected repos/tests + a small versioned migration plan. *Verify:* a known deprecated integration → a task with a real deadline + a verified replacement before closure. Constraint: fetched content = evidence; pin adopted revisions; no auto-adoption of unreviewed instructions. Src: langfuse compatibility, typespec breaking-change-policy.
- **X-28** — Propagate proven shared-component fixes *(cross-product eng)*: fix the owning component once, publish the compatible version, coordinate consumer canaries + linked OpenSpec changes. *Verify:* ≥2 relevant consumers demonstrate corrected behavior on their deployed versions + downstream compat + current capsules. Constraint: consumers differ; one test ≠ every integration; no fleet-wide forced upgrade without rollout authority. Src: backstage system-model, changesets, pact.
- **X-29** — Prove replacement-product compatibility *(positioning)*: a scoped compatibility harness for a replacement (Crawl.Cheap / Browse.Tools); publish truthful supported-subset evidence. *Verify:* a representative existing client completes the supported workflows with only documented config changes + explicit deviations. Constraint: no all-client-compatibility claim from matching paths; don't copy insecure undocumented behavior. Src: openapi spec, typespec for-openapi-dev.
- **X-30** — Evaluate the autonomous loop itself *(agent governance)*: sanitized replayable cases test scheduling / research / routing / recovery / truthful-completion; canary skill improvements before wider rollout. *Verify:* injected stale-data / missing-creds / duplicate-incidents / ambiguous-side-effects → the intended bounded action + honest status. Constraint: eval providers/callbacks execute code — isolate; never weaken requirements to pass the suite. Src: promptfoo tracing, expected-outputs/javascript.
