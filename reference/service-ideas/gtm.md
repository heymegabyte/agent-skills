# Google Tag Manager — service-idea catalog (GTM-01…30)

30 reusable tag-governance improvement HYPOTHESES absorbed from REVISION-2 Appendix D5 (research date 2026-10-28). Reusable METHODS to assess against each project's real evidence — NOT claims about any account, NOT live product state (§23.9 / §19.3). Pointed to by `rules/observability-ops-supervisor.md`.

## Global constraints (apply to every GTM idea)

- **Customer-analytics tenant boundary (loop invariant):** tenant tag code must NEVER execute in the platform editor/admin, another tenant, or an unauthorized preview; no owner tracking IDs on customer sites by default; unknown container/tenant mapping fails CLOSED. GTM is code execution — it must not gain platform privileges.
- No PII / secrets / customer content / sensitive attributes in payloads; sanitize URLs/titles/search/forms (hashing PII is NOT an exception). Consent applies to browser + server. GTM config is NOT the source of business truth.
- Account reads ≠ writes; publish ONLY the authorized container/env/version with recorded validation + live-state evidence; a successful API 200 ≠ correct tags. Reuse shared event contracts (no duplicate producers).

## Adapter notes (§23.10 — verify against installed versions)

- Use ONE fleet-wide admission budget per API project + cache config snapshots so ~30 checks reuse one read. Distinguish quota-403 from authorization-403. Inspect version compilation, publish the EXACT authorized version, verify the live version, test downstream delivery. `set_latest` changes a baseline — it does NOT publish.

## Ideas

- **GTM-01** — One versioned data-layer contract *(event architecture)*: a small typed dispatcher with stable names / safe params / schema version / destination + consent rules. *Verify:* contract-test payloads + replay one event through intended tags, no stale field carryover. Constraint: GTM config ≠ business truth; no PII/creds/object-dumping; don't reset the shared dataLayer. Src: datalayer, event-parameters.
- **GTM-02** — Instrument SPA navigation once *(SPA)*: choose explicit data-layer nav OR history-based tracking, remove the overlap. *Verify:* test first-load + all nav modes in preview with exactly the intended pageviews. Constraint: disable the overlapping auto history path; sanitize location/title/referrer. Src: measure-spa-gtm.
- **GTM-03** — Standardize ecommerce tag mappings *(revenue instrumentation)*: map item/txn/currency/value consistently from confirmed app events. *Verify:* preview a full purchase/refund + validate payloads vs official semantics. Constraint: don't infer paid from a thank-you URL; no card/address; repeated nav ≠ recreate the txn. Src: ecommerce?client_type=gtm, validate-ecommerce.
- **GTM-04** — Measure accepted form outcomes not raw submits *(lead instrumentation)*: trigger lead-success on an explicit server-accepted event, keep error/step categories separate. *Verify:* test invalid/reject/timeout/retry/accept + intended tag count. Constraint: no field values / PII-labels / message-text; a generic form-submit may fire without processing. Src: datalayer, 9216061, 6366371.
- **GTM-05** — Media/content actions with useful context *(content measurement)*: deliberate triggers distinguishing meaningful engagement from autoplay/repeat-visibility. *Verify:* preview media start/progress/complete + download across embeds + consent states. Constraint: check enhanced measurement first (no dup); no signed URLs/tokens/PII filenames. Src: 9216061, datalayer.
- **GTM-06** — Safe search-result outcomes *(search instrumentation)*: map app-provided intent-category / count-bucket / refinement / selection WITHOUT reading the raw query from the DOM. *Verify:* test zero/refine/select + a fake-PII query → no sensitive text leaves the page. Constraint: turn off overlapping raw auto search-term; no hashed-PII substitute; bounded cardinality. Src: datalayer, 9216061, 6366371.
- **GTM-07** — Stable measurement for shared CTA components *(component instrumentation)*: emit semantic CTA events from shared components so redesigns preserve measurement. *Verify:* test keyboard/touch/nested/disabled/route-change, no CSS-text scraping. Constraint: no dynamic button text with customer content; exclude non-actionable impressions + dup handlers. Src: datalayer, 7679318.
- **GTM-08** — Connect actual experiment exposure *(experiment instrumentation)*: forward stable experiment/variant IDs AFTER the user sees the variant. *Verify:* test delayed-render / re-render / nav / multi-experiment / consent-withdraw. Constraint: GTM doesn't pick a winner or replace the engine; assignment ≠ exposure if never rendered; no per-user IDs. Src: integration, datalayer.
- **GTM-09** — Connect signup/activation to confirmed lifecycle *(product instrumentation)*: map confirmed signup/login/first-success/trial/upgrade via the common dispatcher + tenant-authorized tags. *Verify:* each event fires at its documented transition, not on every mount/visit. Constraint: no email/tokens/raw-account; an opaque ID only when justified + consented + non-PII. Src: 12229021, datalayer.
- **GTM-10** — Keep related-domain tagging coherent *(cross-domain config)*: audit deployment/config so authorized related domains use the intended setup + preserve handoff params. *Verify:* test nav + checkout handoffs with preview/network + downstream session. Constraint: prefer GA4 Admin config; don't link independent tenant sites; exclude auth/token URL params. Src: cross-domain, api/v2.
- **GTM-11** — Eliminate duplicate Google tags/destinations *(tag topology)*: find overlapping installs, consolidate the intended path, preserve legit destinations. *Verify:* compare network/event counts before/after + verify destination IDs. Constraint: Google-tag/GTM optimization may change account links/perms; don't combine customer + owner destinations. Src: 13438166, 17079602, api/v2.
- **GTM-12** — Initialize consent before measurement *(consent ordering)*: supported template consent APIs + Consent Initialization so defaults precede measurement. *Verify:* test clean profiles + async CMP + region defaults with Tag Assistant + network/storage. Constraint: don't use Custom-HTML gtag consent as a substitute; no collection before required consent. Src: consent, consent-debugging.
- **GTM-13** — Reliable consent withdrawal/changes *(consent lifecycle)*: propagate updates consistently, stop disallowed future collection on change. *Verify:* test grant→deny / deny→grant / nav / reload / multiple containers. Constraint: don't replay previously-suppressed personal activity; a technical flag ≠ lawful authorization. Src: 10718549, consent-debugging.
- **GTM-14** — Block personal data at the source *(privacy instrumentation)*: safe source values + redaction/allowlist before tags; remove secret query params + personal text. *Verify:* inject fake email/token/address + inspect every outgoing payload. Constraint: GA auto-redaction is best-effort; no real secrets in fixtures; hashing PII is not acceptable. Src: 13544947, 6366371, templates/permissions.
- **GTM-15** — Isolate tenant containers from the platform editor *(multi-tenant security)*: load customer-selected containers ONLY on authorized customer public surfaces; keep platform analytics separate. *Verify:* assert no tenant tag runs in editor/admin / another-tenant / unauthorized-preview + inspect destination traffic. Constraint: unknown mapping fails closed; GTM is code-exec with no platform privilege; no owner IDs on customer sites by default. Src: restrict, api/v2, 6107011.
- **GTM-16** — Environments separate test/prod tags *(release isolation)*: explicit environment usage; prevent preview/staging from sending prod conversions. *Verify:* same journey in test vs prod → correct version/destinations. Constraint: keep env auth params private; no conflicting Git-branch policy; env alone ≠ full destination isolation. Src: 6311518, 6107163.
- **GTM-17** — Isolated workspaces for concurrent changes *(change control)*: a workspace per coherent change, reconcile getStatus/sync before a version. *Verify:* simulate overlapping edits → conflict handling preserves both intents, no silent overwrite. Constraint: workspace isolation ≠ publish permission; check limits + stale lifecycle; sync ≠ a semantic-conflict resolver. Src: workspaces/getStatus, /sync, /workspaces.
- **GTM-18** — Reviewable container-config changes *(config as code)*: store approved config projections + semantic diffs with the repo change, excluding secrets/tenant data. *Verify:* re-read fingerprints before writes + show add/remove/trigger/destination/permission changes. Constraint: the live container is a distinct deployment state; don't overwrite unexpected remote edits from a stale snapshot. Src: workspaces, versions/live, api/v2.
- **GTM-19** — Gate releases on preview + compilation evidence *(release verification)*: quick preview / version-compilation + template tests + browser tag assertions before publish. *Verify:* check compiler/sync errors + fired/not-fired tags/payloads/consent on real journeys. Constraint: an API 200 ≠ correct tags; quick-preview ≠ published; no real purchases / prod-audience from tests. Src: quick_preview, create_version, templates/tests.
- **GTM-20** — Publish exact versions with verified rollback *(deployment)*: publish ONLY the authorized version, record evidence, check the live version, keep a tested rollback. *Verify:* after publish fetch the live version + repeat smoke; rehearse republishing a known-good version in test. Constraint: `set_latest` ≠ publish; no auto-publish without standing authz; read compilerError + fingerprint preconditions. Src: versions/publish, /live, 6107163.
- **GTM-21** — Reversible emergency tag pause *(incident response)*: prepare a minimal pause/removal version, deploy under incident authority, preserve the previous config. *Verify:* the incident stops + critical functions work + resumption is deliberate. Constraint: a workspace-pause ≠ live-stopped; don't disable unrelated measurement; record scope/owner/evidence/recovery. Src: 7679308, 6107163.
- **GTM-22** — Restrict tag code + network permissions *(supply chain)*: prefer reviewed sandboxed templates; narrow permissions + hosts; reduce arbitrary code. *Verify:* template tests + browser CSP/permission checks, legit measurement still works. Constraint: no unsafe-eval / broad-CSP to make tags run; sandboxing ≠ unreviewed-template OK. Src: sandboxed-javascript, templates/permissions, policies, csp.
- **GTM-23** — Reduce the tag performance tax *(web perf)*: remove obsolete tags, cut excessive triggers, defer nonessential work compatible with consent/order. *Verify:* before/after real-browser perf + necessary events still arrive. Constraint: server-side doesn't remove all client cost; don't break consent/order; measured, not a fixed tag-count target. Src: 7679318, server-side/intro.
- **GTM-24** — Explicit tag dependencies + failures *(execution ordering)*: supported sequencing only where needed + defined failure behavior, not arbitrary priority. *Verify:* test setup success/fail/timeout/missing-vars; user actions don't block indefinitely. Constraint: sequenced tags can ignore triggers (audit consent); no business txn depends on analytics completing. Src: 6238868, 7679318, consent-debugging.
- **GTM-25** — Replace brittle DOM triggers with semantic events *(reliability)*: move high-value measurement to explicit app events; keep narrow tested DOM triggers only where there's no app integration. *Verify:* localization / redesign / keyboard / nested tests + intended events. Constraint: no scraping arbitrary page/user text; schema changes versioned across consumers. Src: datalayer, 7679318.
- **GTM-26** — Evaluate server-side tagging for an evidenced need *(architecture)*: pilot a server container when it improves governance/perf enough; keep consent + a bounded budget. *Verify:* preview/live separation + health/scaling/latency/payload-filter + equivalent outcomes. Constraint: Cloud Run / supported Docker (NOT native Workers); don't evade consent; no paid service without authz. Src: server-side/manual-setup, cloud-run-setup, intro.
- **GTM-27** — Each server destination only required fields *(server data minimization)*: per-destination allowlist/removal transforms before forwarding. *Verify:* inspect transformed data + outgoing requests + test omitted-required + malicious-extra fields. Constraint: allow-param transforms can remove required Google-tag fields (test); no PII/secret enrichment; still consent + tenant bound. Src: server-side/transformations.
- **GTM-28** — Route shared events by destination + consent purpose *(multi-tool delivery)*: one semantic producer, map only allowed fields to each destination. *Verify:* each destination gets its event once + nothing under disallowed consent/tenant. Constraint: one consent type ≠ all tools; no customer-data fan-out to owner accounts; don't reimplement app logic in GTM. Src: datalayer, 10718549, 13438166.
- **GTM-29** — Quota-aware drift + health intake *(operations)*: read on deploy + at a bounded daily cadence, compare offline, dedupe drift, serialize via a per-project rate limiter. *Verify:* simulate quota-403 / permission-403 / expired / pagination / partial → unknown not healthy. Constraint: the GTM config API ≠ event-delivery telemetry; default quota is project-wide (shared); don't create projects to evade or blind-retry 403s. Src: api/v2/limits-quotas, versions/live, api/v2.
- **GTM-30** — Maintainable template + access ownership *(governance)*: review upstream template changes + unused access; an accountable owner + rollback + a tested maintenance path. *Verify:* template regression tests before an approved upgrade + re-read permissions after authorized changes. Constraint: no auto invites / role-escalation; don't update every template just because newer; retain provenance + review new permissions/destinations. Src: templates/tests, 6107011, templates/permissions.
