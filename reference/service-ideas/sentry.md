# Sentry — service-idea catalog (SEN-01…30)

30 reusable improvement HYPOTHESES absorbed from REVISION-2 Appendix D1 (research date 2026-10-28). These are reusable METHODS to assess against each project's real evidence — NOT claims about any account, and NOT live product state (§23.9 / §19.3). Pointed to by `rules/observability-ops-supervisor.md`. Each project gives an idea its own applicability/owner/status; the full per-idea signal/action detail lives in the REVISION-2 spec.

## Global constraints (apply to every SEN idea)

- Missing data / absent permissions / no rows = UNKNOWN, never zero or healthy. Scope to authorized projects + environments.
- No PII/secrets/customer-content in telemetry; sampling + repeats affect raw counts (≠ unique users or revenue).
- Dedupe ONE underlying incident across tools; reproduce/regression-verify before resolving; correlation is a hypothesis, not cause.

## Adapter notes (§23.10 — verify against installed versions)

- Use modern issues/feedback APIs + cursor/filter contracts. The LEGACY user-feedback endpoint omits current-widget submissions → use the issue API filter `issue.category:feedback`.
- Cloudflare instrumentation: verify env-access patterns; place Workflow step spans inside `step.do` so re-entry doesn't duplicate them. Feature-flag correlation + custom-uptime-response-verify are beta/early-access — feature-detect + check plan.

## Ideas

- **SEN-01** — Prioritize defects by user/business impact *(reliability)*: rank reproducible defects by reach × journey-criticality × severity × recurrence; one task per incident. *Verify:* triage→verified-recovery time + recurrence. Src: sentry.io/api/events, /api/explore timeseries.
- **SEN-02** — Gate release expansion on release health *(release)*: canary session-health/error/adoption vs a matched baseline → continue/pause/rollback. *Verify:* crash/error-free sessions + journey-failure over a sufficient window. Src: releases/health, release-health-session-statistics.
- **SEN-03** — Contain feature-flag regressions *(rollout)*: attach OpenFeature eval context, compare exposed cohorts, revert the suspect flag + add a regression test. *Verify:* error + journey recover post-change. Constraint: tracking open-beta, latest-100-evals/event. Src: issue-details/feature-flags.
- **SEN-04** — Route repairs via release commits + code ownership *(throughput)*: build an incident context pack (likely files + owner), assign a bounded repair. *Verify:* correct-owner rate + reproduce + repair lead time. Constraint: suspect commit = hypothesis; Seer stops before an unapproved PR. Src: releases/associate-commits.
- **SEN-05** — Verify source-map + release identity *(debuggability)*: build-step asserts a sentinel bundled error resolves to the correct original file:line; repair mismatched artifacts. *Verify:* sentinel shows intended source+commit; %actionable stacks. Constraint: upload creds server-side; don't expose private source. Src: sourcemaps.
- **SEN-06** — Reduce duplicate issues without hiding distinct failures *(signal quality)*: fix demonstrated over/under-grouping with tested fingerprint rules; dedupe tasks by org/project/issue + incident epoch. *Verify:* replay events → expected grouping; dup-task volume down, coverage intact. Src: event-grouping.
- **SEN-07** — Instrument critical journeys by verified outcome *(product reliability)*: bounded privacy-safe journey stages + failure reasons. *Verify:* end-to-end + stage failure/latency; count success only on authoritative confirm. Constraint: outcome IDs, never form/payment/doc contents. Src: /api/discover/trace, metrics.
- **SEN-08** — Improve slow LCP by evidence *(frontend loading)*: optimize the dominant image/font/server-response/render on a poor-p75-LCP route. *Verify:* matched RUM p75 LCP + Browser-Run before/after + error/conversion guardrails. Constraint: Web-Vitals dash covers initial loads, not all SPA navs. Src: dashboards/web-vitals.
- **SEN-09** — Reduce INP in editors/dashboards *(responsiveness)*: split/defer expensive work, cut renders, offload the main thread. *Verify:* p75 INP + action latency + interaction/cancel regressions. Constraint: browser profiling is beta. Src: web-vitals, profiling.
- **SEN-10** — Eliminate disruptive layout shift *(visual stability)*: reserve media/async dims, stabilize font/loading, fix moving overlays. *Verify:* RUM CLS + screenshot/interaction at 3 sizes incl loading/error. Constraint: replays need masking + consent. Src: web-vitals, session-replay/privacy.
- **SEN-11** — Repair hydration mismatches at source *(rendering)*: deterministic server/client initial state, fix invalid markup, isolate client-only; add SSR→hydration tests. *Verify:* warnings gone + content/a11y/interactions correct. Constraint: replay diff imperfect; don't blanket-suppress. Src: replay-issues/hydration-error.
- **SEN-12** — Rage/slow-clicks → interface repairs *(UX friction)*: fix nonresponsive controls, disabled-state clarity, missing feedback, hit targets. *Verify:* reproduce + repeated-click incidence + completion post-fix. Constraint: print/download can mislead; narrow exclusions only. Src: replay-issues/rage-clicks.
- **SEN-13** — Remove render-blocking/uncompressed assets *(delivery)*: split/defer, fix CDN/server compression, keep cache keys/types. *Verify:* prod headers + transferred bytes + first-paint + functional/visual regressions. Constraint: detectors have thresholds; use real deployed resources. Src: large-render-blocking-asset, uncompressed-asset.
- **SEN-14** — Remove sequential API waterfalls *(latency)*: parallelize independent calls / batch / aggregate endpoint; respect cancel + provider limits. *Verify:* critical-path latency + request count + ordering/failure/ratelimit. Constraint: never parallelize dependent/non-idempotent calls. Src: consecutive-http, /trace.
- **SEN-15** — Tune the most expensive DB ops *(data perf)*: inspect query plans + indexes, optimize the highest-impact op with realistic data + rollback. *Verify:* p95 query+endpoint latency + correctness + write overhead. Constraint: parameterized/redacted shapes; CF binding instrumentation applies to wrapped env. Src: cloudflare/bindings, /trace.
- **SEN-16** — Replace N+1 with bounded batches *(data access)*: joins / batch-loaders / bulk; preserve pagination + authz + ordering. *Verify:* query count vs input size + equivalent results + tenant isolation. Constraint: detector threshold ≠ absence proof; no user values in SQL. Src: n-one-queries.
- **SEN-17** — Tune caches by hit/miss/staleness *(caching)*: fix keys/TTL/invalidation/stampede on high-impact endpoints; keep tenant + authz. *Verify:* hit ratio + origin reqs + p95 + stale/wrong-response under concurrency. Constraint: higher hit ratio ≠ success if cross-tenant/stale. Src: dashboards/caches.
- **SEN-18** — Prevent queue backlog missing deadlines *(throughput)*: adjust batching/concurrency or split constrained consumers; prioritize email/browser/publish jobs. *Verify:* oldest-message-age + throughput, no downstream errors/lost work. Constraint: CF send spans ≠ full coverage; use an authoritative counter. Src: dashboards/queues, bindings, metrics.
- **SEN-19** — Stop retry storms + repeated side effects *(correctness)*: bounded backoff + poison handling + idempotency; reconcile uncertain external outcomes before redispatch. *Verify:* inject failure+dup → bounded attempts + one accepted outcome + visible unknown. Constraint: Workflow spans inside `step.do`. Src: workflows, logs, metrics.
- **SEN-20** — Detect missed/stalled recurring jobs *(scheduler)*: monitor loop dispatch + backups/reports/content; catch-up on miss/stall. *Verify:* simulate missed/stuck/failed → detection + catch-up + ledger debt. Constraint: a check-in ≠ a successful outcome; don't use the failed scheduler as its own watchdog. Src: monitors/crons.
- **SEN-21** — Detect outages independent of traffic *(availability)*: read-only endpoint checks with noise-resistant thresholds → diagnose + approved recover. *Verify:* isolated failure → detect + trace link + recover + unknown-handling. Constraint: no secrets in monitor headers. Src: monitors/uptime.
- **SEN-22** — Reduce CPU hotspots via profiling *(runtime)*: optimize the dominant stack / remove redundant processing with workload benchmarks. *Verify:* CPU/time per op + p95 + correctness incl profiling overhead. Constraint: Node profiling ≠ Workers; browser/.NET beta/experimental. Src: profiling.
- **SEN-23** — Repair cohort-specific compat failures *(browser compat)*: reproduce on the target engine, add progressive-enhancement/fallback (not degrade-all). *Verify:* journey on the real engine + post-release cohort error. Constraint: Browser-Run engine coverage must be verified; Chromium ≠ Safari/Firefox. Src: /api/events, /api/explore.
- **SEN-24** — Contextual feedback → verified fixes *(support)*: cluster concrete problems + a minimal repro pack → fix the defect/workflow. *Verify:* reproduce + improved workflow + repeat-feedback/resolution time. Constraint: legacy feedback endpoint omits widget submissions → `issue.category:feedback`; minimize/redact. Src: user-feedback.
- **SEN-25** — Improve third-party integration resilience *(dependencies)*: timeout / bounded-retry / circuit-breaker / cached-fallback / user-recovery for a demonstrated provider failure. *Verify:* test timeout/429/5xx/invalid/recover + task success + call volume. Constraint: verify provider retry/idempotency; never blind-retry a POST. Src: /trace, logs.
- **SEN-26** — Recoverable errors preserve user work *(failure UX)*: draft preservation + retry/resume + cancel + useful errors tied to real state. *Verify:* reproduce interruption+recovery with no lost drafts/dup-writes/false-success. Constraint: drafts in the established data model, not Sentry. Src: user-feedback, /trace, replay/privacy.
- **SEN-27** — Detect noisy-neighbor, protect tenant fairness *(multitenant)*: find shared bottlenecks → admission control / per-tenant limits / separation. *Verify:* concurrent tenant loads → tail latency + errors + fairness, no cross-tenant exposure. Constraint: pseudonymous IDs; metrics ≠ isolation proof. Src: /api/explore, metrics.
- **SEN-28** — Privacy-safe diagnostics by construction *(confidentiality)*: centralize redaction + replay-blocking in SDK adapters + design-system; audit errors/spans/logs/URLs/attachments. *Verify:* a synthetic canary never leaves the process/artifacts. Constraint: post-ingestion masking is too late; default replay masking not guaranteed after a UI change. Src: sensitive-data, replay/privacy.
- **SEN-29** — Balance telemetry coverage/noise/spend *(observability economics)*: tune filters/sampling, fix duplicate SDK init, keep critical-path coverage. *Verify:* sentinel still observable + dropped-event causes understood + evidence/cost improves. Constraint: fewer events may = broken instrumentation; estimates ≠ invoices. Src: query-dropped-events, event-counts.
- **SEN-30** — Detect silent persistence/publication failures *(data integrity)*: bounded integrity reconcile for critical writes; fix false-success/partial-commit. *Verify:* inject partial failure → UI/ledger shows the true durable state + discrepancy/recovery time. Constraint: Sentry transports evidence, doesn't validate storage; use metadata/synthetic, never full docs. Src: metrics, logs, /trace.
