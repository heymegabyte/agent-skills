# PostHog — service-idea catalog (PH-01…30)

30 reusable product-analytics improvement HYPOTHESES absorbed from REVISION-2 Appendix D3 (research date 2026-10-28). Reusable METHODS to assess against each project's real evidence — NOT claims about any account, NOT live product state (§23.9 / §19.3). Pointed to by `rules/observability-ops-supervisor.md`.

## Global constraints (apply to every PH idea)

- **Customer-analytics tenant boundary (loop invariant):** owned platforms use OUR configured destinations; customer-generated OnePrompt sites get NO platform-owner marketing/replay tags by default — tenant-owned config, consent, removal + access controls enforced. Group/tenant labels are attribution, NOT authorization.
- A successful API call / emitted event / plausible answer / green judge ≠ the intended outcome; observational association is a hypothesis, not cause. Define value as a CONFIRMED user outcome, not a login/click.
- No secrets / raw email / clipboard / editor-or-customer text / repo bundles. Evidence records carry window + observed_at + freshness + sample/denominator + cohort + cached/partial state. Dedupe by underlying issue. Predeclare experiment rules. Bound API work (quotas/concurrency/timeout/retry/spend); respect plan availability.

## Adapter notes (§23.10 — verify against installed versions)

- Use bounded aggregate investigations + saved-query freshness metadata. Do NOT run recurring bulk events/persons/query_log exports through `/query` — use supported batch/file exports or destinations. Prefer keyset pagination over OFFSET (verify tie-boundary + dedupe). Capture tokens do NOT authorize reads/admin; check OAuth/private-key + plan + experimental-feature support.

## Ideas

- **PH-01** — Remove the largest first-value onboarding bottleneck *(activation)*: investigate the biggest drop in the signup→first-success funnel, simplify that step. *Verify:* completed first-value / eligible-signup with a predeclared window + min sample + Browser-Run. Constraint: value = a confirmed outcome, not login/click. Src: activation, funnels.
- **PH-02** — Shorten time to first usable result *(activation)*: remove waits, prefill defaults, show a partial result during setup. *Verify:* p50/p90 elapsed down without lowering completion/quality (equivalent workload cohorts). Constraint: track abandoned/timed-out separately. Src: funnels, trends.
- **PH-03** — Repair navigation loops/dead-ends *(IA)*: fix the confusing label / missing next-step / broken route from a path insight + redacted replay. *Verify:* lower loop frequency + better next-step completion across viewports. Constraint: normalize dynamic routes, exclude internal; paths ≠ intent. Src: paths.
- **PH-04** — Prioritize errors by lost outcomes *(reliability)*: add user-impact evidence to the Sentry issue/task, fix journey-blocking ones. *Verify:* journey recovery + lower issue-linked failure post-fix. Constraint: Sentry stays the error authority (no dup); correlation = triage, not cause. Src: correlation, session-replay.
- **PH-05** — Fix misleading controls from frustration signals *(interaction)*: repair hit targets / disabled-clarity / feedback / false-affordance from rage-dead-clicks + replay. *Verify:* lower frustration-session rate, maintain completion. Constraint: heuristic not proof; respect masking + review budget. Src: data-pipelines, replay pocket-guide.
- **PH-06** — Optimize slow pages with business impact *(web perf)*: fix the slow asset/render/layout on the highest-impact page joined to abandonment/conversion. *Verify:* prespecified LCP/INP/CLS percentiles + no real-user completion regression. Constraint: keep percentile/sampling/window consistent; field vs lab. Src: web-vitals.
- **PH-07** — Investigate responsive/accessible interaction failures *(a11y)*: reproduce viewport/input-mode completion gaps via keyboard/zoom/a11y checks; fix focus/labels/layout/targets. *Verify:* a11y checks + affected-journey completion, no cohort harm. Constraint: analytics ≠ WCAG/disability; coarse metadata only. Src: correlation, surveys.
- **PH-08** — Reduce auth/recovery abandonment *(account access)*: improve recovery guidance / expired-link / return-to-task from sanitized stage+reason events. *Verify:* legit recovery completion up + repeat failures down, security intact. Constraint: never capture passwords/tokens/raw-auth-URLs. Src: funnels, libraries/js.
- **PH-09** — Improve unsuccessful in-product search *(findability)*: synonyms/suggestions/empty-state/missing-content for a no-result/reformulation cluster. *Verify:* no-result + reformulation down, result→task up. Constraint: sanitized categories not raw query text; check sample bias. Src: trends, libraries/js.
- **PH-10** — Expose features at the point of need *(adoption)*: contextual affordances / clearer entry point, not generic tours. *Verify:* successful feature-use among eligible + the underlying task outcome, retention guardrail. Constraint: exposure/click/success are distinct; adoption ≠ value if optional. Src: paths, feature-flags.
- **PH-11** — Improve editor-to-publish completion *(creation)*: fix the stage causing abandonment / failed-publish incl resumable recovery, linked by artifact ID. *Verify:* unique artifacts reaching the requested remote state + fewer repeat attempts. Constraint: a publish-click ≠ success (backend-confirm); no draft content to analytics. Src: funnels, data/sessions.
- **PH-12** — Measure useful AI outcomes per cost *(AI economics)*: prioritize expensive low-success workflows via sanitized run IDs + accept/correct events + Langfuse cost/quality. *Verify:* accepted outcomes per $ and per minute, hold a quality floor. Constraint: Langfuse = AI-trace authority; dedupe runs, retries ≠ new tasks. Src: sql, trends.
- **PH-13** — Repair weak retained cohorts *(retention)*: fix the onboarding/limitation linked to poor return, by activation path/release (mature cohorts). *Verify:* the specified return interval for comparable mature cohorts + counts/uncertainty. Constraint: don't compare incomplete vs mature; stable event/interval/method. Src: retention.
- **PH-14** — Support the natural repeat-use cadence *(recurring value)*: saved workflows/templates/return-state for legitimately-repeated tasks. *Verify:* successful work periods per active-user up, no unwanted notifications. Constraint: don't optimize raw engagement; a monthly product ≠ a daily target. Src: stickiness.
- **PH-15** — Address established-user dormancy *(lifecycle)*: fix the product cause / in-product return path for a material dormancy rise. *Verify:* avoidable dormancy down + sustained resurrection over complete intervals. Constraint: lifecycle = identified activity; outbound reactivation needs comms authorization. Src: lifecycle, cohorts.
- **PH-16** — Improve org activation + collaboration breadth *(B2B)*: fix invites / role-clarity / collab-onboarding where an activated individual fails to activate the account. *Verify:* activated accounts + collaborating members per eligible-account, no perms regression. Constraint: group analytics is a PAID add-on (verify entitlement/cost); groups = association not authz; 5-group-type limit. Src: group-analytics.
- **PH-17** — Test clearer plan/upgrade explanations *(monetization)*: experiment clearer limits/value/comparison, terms controlled. *Verify:* qualified upgrade conversion with refund/cancel/support guardrails. Constraint: predeclare primary/unit/sample/duration/audience; no unauthorized pricing or misleading urgency. Src: experiments, analyzing-results.
- **PH-18** — Remove legitimate checkout failures *(revenue)*: fix validation/payment-method/redirect/recovery blocking real transactions, reconciled to server-confirmed payment + unique order ID. *Verify:* unique paid orders per eligible-checkout up + fewer repeat-payment/support. Constraint: client-clicks + repeat-webhooks ≠ double-count; no card data. Src: funnels, revenue-analytics/managed-views.
- **PH-19** — Reduce preventable subscription revenue loss *(revenue retention)*: fix product/billing-UX churn causes via reconciled changes/refunds/failed-renewals + usage. *Verify:* net retained revenue + recovered renewals + complaints with consistent currency/defs. Constraint: verify sync freshness (append-only Stripe misses updates); Revenue Analytics is beta, managed views are SQL-only. Src: revenue-analytics/stripe, managed-views.
- **PH-20** — Make usage limits/trial transitions clear *(trial/entitlement UX)*: progress visibility + graceful save/resume + an accurate next-option from limit-reached events. *Verify:* lost work + repeat limit-errors down + informed upgrade/continued-use. Constraint: entitlement checks stay server-authoritative; exclude recently-changed plan until synced. Src: cohorts, trends.
- **PH-21** — Contextual feedback → product fixes *(voice of customer)*: a short targeted in-app survey after a meaningful task; cluster + validate concrete problems → one deduped fix. *Verify:* response count/rate + problem prevalence + changed task success. Constraint: self-selected evidence ≠ population; wait periods + caps; free text is sensitive. Src: surveys, creating-surveys.
- **PH-22** — Improve cancellation + learn churn causes *(trust/churn)*: fix recurring unmet-needs/confusion, keep cancellation easy; non-obstructive alternatives only. *Verify:* fast cancellation maintained + recurring avoidable churn down. Constraint: never obstruct to raise retention; feedback optional, no auto-contact. Src: creating-surveys, lifecycle.
- **PH-23** — Prevent false experiment winners *(experiment integrity)*: detect broken assignment/tracking or invalid stopping before adopting; correct or mark inconclusive. *Verify:* an A/A or known-control fixture + effect estimates with the chosen fixed-horizon/sequential rule. Constraint: frequentist sequential must be ENABLED before peeking; predeclare primary/guardrail + multiple-comparisons. Src: experiments/statistics-frequentist, analyzing-results.
- **PH-24** — Roll out risky changes by user outcomes *(release safety)*: advance/hold/revert via flag exposure + success/errors/perf for a canary vs comparable. *Verify:* assignment + a tested off-path + recovery after rollback. Constraint: flags need safe fallbacks (an off-flag ≠ reversing a migration); server eval + authz; no 2nd deploy controller. Src: feature-flags.
- **PH-25** — Retire stale flags/variants *(maintainability)*: remove obsolete branches/config after verifying stable behavior, from usage/status + code refs + decisions. *Verify:* lower stale inventory + behavior preserved with tests + release evidence. Constraint: no-recent-calls may = missing telemetry; check exposure semantics + scheduled-changes + rollback deps. Src: feature-flags, surfaces/web-app.
- **PH-26** — Content that leads to successful use *(content/growth)*: update/create the explanation users need, then measure the downstream product task. *Verify:* task completion / qualified-activation after content exposure; track support burden, not pageviews. Constraint: GA4 owns the acquisition role (no conflicting attribution); owned content only, customer sites tenant-owned. Src: web-analytics/dashboard, paths.
- **PH-27** — Repair connector setup + first-sync failures *(integration adoption)*: fix permission-explanation / token-recovery / connector-first-sync from sanitized stage+reason events. *Verify:* working connections + successful first-import per eligible-setup, fewer retries. Constraint: never emit OAuth tokens/codes/imported records; a redirect ≠ working. Src: funnels, libraries/js.
- **PH-28** — Repair event-schema + identity drift *(measurement quality)*: fix missing/renamed/duplicated/misattributed events, keep repo-owned contracts authoritative. *Verify:* a synthetic signup/login/logout/task journey → expected project + correct IDs + one logical outcome. Constraint: PostHog schema CLI is experimental; compile-time types ≠ ingestion-correct; reset identity on logout. Src: schema-management, identify-users.
- **PH-29** — Verify consent/masking/tenant-destination boundaries *(privacy/isolation)*: fix SDK init / masking / routing / removal so each surface sends only approved data to the intended destination. *Verify:* inspect network payloads + destination visibility; canaries absent + customer sites carry no owner IDs by default. Constraint: input masking ≠ masking all text/URLs/logs; group labels = attribution not authz. Src: session-replay/privacy, libraries/js.
- **PH-30** — Feed fresh deduped evidence to the loop *(automation/evidence ops)*: upsert one finding per project+metric+cohort+regression-episode, link a bounded fix + remeasure. *Verify:* repeated intake → no dup task; stale/partial can't claim recovery; a simulated regression is detected + resolved within budget. Constraint: `/query` for small aggregates not bulk export; keyset pagination; cached-freshness + Retry-After + alert-plan; no 2nd code editor. Src: api/queries, api, alerts.
