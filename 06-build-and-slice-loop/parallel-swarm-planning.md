# Top 15 Frontier Ideas for Leveraging Parallel Swarms of Claude, Codex, Gemini & OpenCode (DeepSeek)

The strategies below inform planning in `bin/prompt-hydrator.ts` and `bin/scrum-deliberation-quorum.ts`. Execution requires approved host adapters for `bin/evidence-gated-orchestrator.ts`:

Schedule independent ready changes concurrently whenever it improves verified turnaround. Delegate all suitable work to OpenCode with DeepSeek via LiteLLM. Refill available approved capacity as dependencies clear. Use Codex, Gemini, or Claude where premium capability or independent review materially improves the result. Treat allocation estimates as planning inputs and verify actual dispatch from scheduler receipts.

1. **Zero-Latency `UserPromptSubmit` Hyper-Saturation & Codebase Gap Audit (`prompt-hydrator.ts`)**:
   Intercept every prompt at submission time to combine skill routing, active OpenSpec reconciliation, and an automatic repository gap scan that detects unfinished surfaces (such as `"Settings"`, `"Billing"`, or missing `@theme.tools/*` adapters) and adds them to the execution contract automatically.
2. **Recursive Categorical Web-Research Saturation & Parallel Plugin-Catalog Factory**:
   Cycle through all 10 product categories (`C01`–`C10`), running parallel web research and competitor benchmarking until zero unaddressed ideas remain, and automatically expand extensible features into full plugin catalogs built by 4–8 parallel `opencode` (DeepSeek) workers.
3. **Dynamic Right-Sized SCRUM Deliberation Quorum (`scrum-deliberation-quorum.ts`)**:
   Convene a contextual SCRUM ceremony with *only* the specialist agents required by the prompt's domain fingerprint (e.g., `architect` + `appsec` + `database-engineer`), avoiding 28-agent chatter while producing a synthesized consensus blueprint and dissent register.
4. **Heterogeneous Tri-Frontier Cognitive Division (`Claude` · `Codex` · `Gemini`)**:
   Exploit uncorrelated model strengths in parallel: **Claude (`opus`)** for system architecture, UI/UX craft, and synthesis; **Codex (`codex`)** for adversarial security/algorithm verification and backend rigor; **Gemini (`gemini`)** for 1M–2M token cross-repo cartography and multimodal visual QA.
5. **Contract-First OpenSpec DAG Compiler (`task-graph.json`)**:
   Lock Zod schemas, Hono RPC routes, and TypeScript interfaces in OpenSpec *before* spawning worker swarms so parallel worktrees compile against immutable boundary contracts with zero integration drift.
6. **OpenCode with DeepSeek as the default for suitable work**:
   Classify every OpenSpec DAG node as `frontier-required` or `throughput-safe`, routing all `throughput-safe` implementation, plugin catalogs, tests, and docs to parallel `opencode` workers over the 4-key LiteLLM DeepSeek rotation pool (`https://llm.megabyte.space/v1`).
7. **Pre-Warmed Ephemeral Git Worktree Pool with Zero-Copy Symlink Hydration (`worktree-pool.sh`)**:
   Maintain a pool of isolated Git worktrees pre-linked to shared `node_modules`, `.wrangler`, `.cache`, and `.turbo` directories so parallel `claude`, `codex`, `gemini`, and `opencode` agents launch in `<300ms` without file locks or index corruption.
8. **Deterministic Per-Worktree Port & Local D1/Miniflare Leasing**:
   Assign each parallel swarm worker a deterministic port block (`4100 + workerIndex * 10`) and isolated Miniflare state directory so multiple agents run dev servers and E2E checks concurrently without `EADDRINUSE` collisions.
9. **Speculative Dual-Harness Racing on Critical-Path Bottlenecks**:
   For high-risk or blocking DAG root nodes, race two heterogeneous harnesses in parallel worktrees (e.g., `claude` vs. `codex`, or `codex` vs. a 3-worker `opencode` DeepSeek tournament) and merge the first candidate that passes all contract and unit tests.
10. **Mid-Task Altitude Downgrade (`Frontier Contract Lock → OpenCode DeepSeek Volume Finish`)**:
    Have frontier agents (`claude` / `codex` / `gemini`) author only the architectural skeleton, type contracts, and failing RED test, then immediately hand off the remaining implementation and 16-state UI completion to an `opencode` DeepSeek swarm.
11. **28-Library `@theme.tools/*` Thin-Shell Extraction & Consumer Convergence Swarm**:
    Whenever reusable components, calculators, workflows, or engines are built, spawn a parallel `opencode` DeepSeek extraction worker to upstream the shared logic into `@theme.tools/*` while keeping the app repository a thin configuration shell.
12. **Parallel Cloudflare Browser Run (`@cloudflare/playwright`) 6-Breakpoint × 16-State E2E Verification Swarm**:
    Fan out E2E verification across Cloudflare's edge browser fleet (`@cloudflare/playwright` bound to `env.MYBROWSER`) covering all 6 breakpoints and 16 visual states in parallel for near-100% journey coverage alongside 100% unit test coverage.
13. **Cross-Family Adversarial Verification & AST Merge Gate**:
    Require every swarm branch to pass a cross-model review (code authored by `opencode` or `claude` is audited by `codex` or `gemini` against OpenSpec scenarios, AST boundary rules, and 100% coverage thresholds) before folding into `main`.
14. **Continuous Parallel Context, Comment & Documentation Enrichment Swarm**:
    Run a background `opencode` DeepSeek documentation worker in parallel with feature waves to keep `README.md`, `AGENTS.md`, `SYSTEM-POSTURE.md`, OpenAPI schemas, and inline JSDoc comments synchronized with web-researched domain truth.
15. **Autonomous Production Finish-Line Pipeline (`main` Commit + Cloudflare Provision + Domain Connect + CDN Purge + Triad Sync)**:
    Fold all verified worktrees into `main`, provision Cloudflare resources and custom domains, deploy via `wrangler deploy`, purge the Cloudflare edge cache, verify live HTTP 200 + security headers, and sync OpenSpec/Paperclip state across `agent-skills`, `install.doctor`, and `theme.tools`.
