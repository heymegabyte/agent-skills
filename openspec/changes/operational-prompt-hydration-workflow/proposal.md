# Proposal

**Architect Role:** assigned

## Why

The repository contains strong but fragmented hydration and orchestration machinery, while the active installed instructions are stale, only Claude has executable prompt interception, multi-model gates reject supported single-agent environments, and checked planning tasks do not prove release-to-consumer or integrated Git delivery. This change makes the requested Prompt Hydration workflow one durable, installed, executable, resumable contract with observable end-to-end evidence.

## What Changes

- Install one concise canonical operating policy, with focused procedural skills and deterministic managed-block generation into supported repository, global, plugin, harness, coordinator, and worker instruction surfaces.
- Name and implement **Prompt Hydration** as the proportional first stage for every engineering request, producing a sparse coverage matrix, recorded assumptions, and complete intended-outcome requirements.
- Replace the hard three-provider gate with a Codex-led architecture conference using product/completeness and architecture/verification responsibilities, combining or running them sequentially when capacity or providers are limited and recording the fallback honestly.
- Compile comprehensive OpenSpec requirements and tasks with durable requirement → task → code → verification → integrated commit traceability, including per-MCP inventory coverage for MCP catalog requests.
- Execute ready work through bounded parallel workers with duplicate-dispatch prevention, one integration writer per repository, maintenance recursion guards, and exact resumable checkpoints.
- Make `theme.tools` the reusable owner and prove the full package release → published version → consumer update chain when a shared capability changes.
- Persist documentation, project lessons, and scoped user preferences throughout implementation, then run confidence-bounded improvement rounds until two refreshed rounds find no qualifying work.
- Reconcile current main, commit and push coherent validated changes, verify remote commits and CI, and preserve precise blockers rather than treating local or generated state as delivery.
- Add behavioral fixtures for an MCP catalog, shared component propagation, single-agent fallback, narrow bug fixes, scoped corrections, interruption/resume, competing writers, blocked releases, and fresh coordinator/worker policy loading.

## Capabilities

### New Capabilities

- `prompt-hydration-workflow`: Proportional outcome hydration, sparse coverage, architecture conference fallback, OpenSpec compilation, recursive improvement, and evaluation fixtures.
- `instruction-policy-distribution`: Canonical policy generation, installation, digest receipts, drift prevention, publish safety, and coordinator/worker loading proof.
- `delivery-traceability`: End-to-end requirement, ownership, execution, verification, commit, remote, release, and consumer evidence with resumable state.

### Modified Capabilities

- `autonomous-mission-expansion`: Bound improvement rounds by evidence, authority, confidence, value, and two-round convergence.
- `autonomous-work-admission`: Admit proportionate small-team and single-agent execution without weakening authorization boundaries.
- `authoritative-work-ledger`: Record task ownership, integration-writer leases, idempotent dispatch, recursion guards, checkpoints, and integrated commits.
- `multi-model-convergence`: Prefer complementary multi-agent review while supporting honest combined or sequential fallback.
- `evidence-integrity`: Distinguish instruction presence, simulated orchestration, live loading, package publication, consumer adoption, remote integration, and runtime verification.

## Impact

- Canonical rules, operating-system/goal/architecture/build/verification/learning skills, OpenSpec schemas and templates, prompt hydrator, conference and swarm runtimes, run-state schemas, generators, publish workflows, fleet sync, approved provider wrappers, and validation suites in `heymegabyte/agent-skills`.
- Installed instruction targets for Codex, Claude, Gemini, OpenCode, Paperclip, OpenClaw, and worker profiles, using supported customization and explicit source revisions.
- `heymegabyte/theme.tools` package/release fixtures and selected consumer fixtures where necessary to prove the reusable-capability chain; product-specific code remains outside the shared packages.
- Git integration on current `main`, normal pushes, CI observation, and exact blocker receipts; no force-push, secret publication, destructive migration, paid-provider substitution, or unapproved external communication.
