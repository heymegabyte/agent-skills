# Proposal

## Why

Agents currently receive fragmented testing guidance and cannot prove that selective execution, TDD history, browser evidence, and deployment verdicts are complete or truthful. A single reusable discipline is needed to encode the 450 required recommendations while keeping the core skill concise and application rollout risk-based.

## What Changes

- Add one concise authoritative TDD/testing skill with progressive family references.
- Account for exactly 15 families and 450 unique recommendation IDs in a machine-readable ledger and schema.
- Add application-profile, requirement-to-test, selection-manifest, evidence, and gate contracts.
- Add selector verification, Browser Run, five-minute CI, cache, budget, evaluation, and report guidance.
- Absorb upstream Superpowers TDD/verification practices through the existing provenance process.
- Require canonical theme.tools assets and ui.theme.tools web components for all application UI and test fixtures; require full-page/full-site Storybook coverage for shared UI.
- Roll out critical-path pilots separately and record planned, blocked, not-applicable, implemented, and verified states honestly.

## Capabilities

### New Capabilities

- `agent-testing-discipline`: Test-first workflow, layer selection, evidence integrity, and risk-based rollout for coding agents.
- `selective-test-orchestration`: Validated affected selection, Browser Run execution, five-minute gate reconciliation, caching, budgets, and artifacts.
- `testing-catalog-traceability`: Exact 450-ID policy accounting, application profiles, requirement-to-test mappings, evaluations, and rollout evidence.

### Modified Capabilities

## Impact

Agent skills, rules, references, evaluation fixtures, schemas, CI templates, router metadata, shared theme.tools test utilities, ui.theme.tools Storybook conventions, and authorized pilot repositories.
