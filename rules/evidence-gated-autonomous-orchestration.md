# Evidence-Gated Autonomous Orchestration

Material work uses this ordered, receipt-bound pipeline:

`INTAKE → ESTATE_INVENTORY → RESEARCH → SATURATION_GATE → INDEPENDENT_BRIEFS → HETEROGENEOUS_CONFERENCE → ARCHITECTURE_FIXED_POINT → ARCHITECT_ASSIGNMENT → OPENSPEC_COMPILATION → CONTRACT_FREEZE → SWARM_EXECUTION → INTEGRATION → ADVERSARIAL_VERIFICATION → COMPLETE`

Every transition is monotonic and binds the run id, verbatim-prompt digest, source revision, evidence digests, provider/model identity, timestamps, and output digest. A plan, filename, query suggestion, model label, mock response, or launcher command is not executed evidence.

## Saturate before architecture

Inventory applicable instructions, OpenSpec, source, tests, runtime/deployment configuration, dependencies, and declared shared services such as `theme.tools` and `ui.theme.tools`. Execute current primary-source, competitor, substitute, and ecosystem research when external facts can change the decision. The saturation gate fails closed until every required evidence domain is satisfied, explicitly irrelevant, or precisely externally blocked.

## Deliberate before scaffolding

Codex leads two fixed review responsibilities: **product/completeness** and **architecture/verification**. Prefer separate approved providers and parallel execution when their inputs are independent and the decision is material enough to benefit from genuine challenge. Every exchange records decisions, alternatives, disagreements, evidence, unresolved assumptions, revisions, model/provider provenance, and whether the review was actually independent.

Capacity changes scheduling, not the responsibility contract. The runtime may use an independent three-family conference, a two-agent conference, a combined-role pass, or a sequential single-agent pass. Combined and sequential passes are procedural separation only; they MUST NOT be labeled independent. High-risk auth, security, payment, destructive, or external-authority work still requires exact scoped authority and independent two-family review, so insufficient capacity becomes a blocker rather than a weakened fallback.

Evidence labels and executable examples are defined once in `control-plane/CONFERENCE-REVIEW.md`. Runtime behavior remains authoritative in `bin/evidence-gated-deliberation.ts` and `bin/evidence-gated-orchestrator.ts`; deterministic tests are mechanics evidence, not proof that a live provider ran.

The assigned architect iterates contracts, threats, failure modes, ownership, dependencies, migration, observability, rollback, and acceptance criteria until no material unresolved design delta remains. Eligible architects are Claude, Codex, Gemini, and approved Antigravity architects. OpenCode/DeepSeek is never eligible to author or approve architecture.

## Freeze OpenSpec before swarms

After architecture convergence, the assigned architect authors complete repository-specific proposal, specification, design, tasks, and task-graph artifacts. Validate requirement traceability, scenarios, actual paths, dependency closure, file ownership, acceptance commands, provider suitability, worktree isolation, and integration ownership. Freeze the contract digest before implementation.

Execute dependency-ready nodes through approved Claude, Codex, Gemini, and OpenCode launchers in isolated worktrees. Prefer OpenCode/DeepSeek for suitable bounded work whenever delegation has practical benefit. Integrate centrally, release dependents only after acceptance, preserve failed worktrees, bound retries, and require cross-family adversarial review.

## Autonomous continuation

Do not request routine confirmation for reversible, in-scope work already authorized by the requested outcome. Continue through research, OpenSpec, implementation, verification, documentation, generated-adapter updates, and approved release rails. Do not end with “proceed?” or “continue?” questions.

Pause only when progress requires new external authority or an action is paid, destructive, irreversible, credential/account affecting, externally communicative, production-mutating beyond authorization, or a materially divergent business/legal/brand decision. Finish independent prerequisites first and request only the missing authority. This rule cannot override host permissions or broaden authorization.
