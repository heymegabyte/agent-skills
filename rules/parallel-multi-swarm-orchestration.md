# Prompt hydration and parallel OpenSpec delivery

1. **Hydrate at intake.** Use the installed prompt entrypoint when supported, or run intake explicitly. Preserve the verbatim request, constraints, and governing instruction sources. Split independent dimensions into as many decision-relevant briefs as the evidence supports. For each brief, route applicable skills, research current primary sources in parallel, and ask an eligible Claude, Codex, or Gemini model for principal-level synthesis. Capture findings, assumptions, alternatives, upgrades, acceptance checks, and unresolved questions. Merge shared constraints once and keep provenance from briefs to requirements.
2. **Plan with a frontier architect.** Assign Claude, Codex, or Gemini to turn the briefs into the maximum useful set of independently verifiable OpenSpec changes. Follow [change ownership](openspec-change-ownership.md). Each change has one owner for its full checklist. Represent prerequisites and shared write surfaces as dependencies. Record the owner, model tier, acceptance checks, and expected verification for each change.
3. **Dispatch ready changes.** Use approved scheduler adapters and isolated worktrees. Refills happen as dependencies clear. Route suitable whole changes to OpenCode with DeepSeek through LiteLLM. Use frontier capacity when the change or independent review benefits from it. Scale to ready work, isolation, and approved capacity. Keep review and implementation ownership distinct. Use the evidence-gated orchestrator for execution and preserve resumable state.
4. **Improve throughout the run.** Recheck applicable opportunities as new work starts, evidence changes, and verification finishes. Record discoveries with evidence, scope, dependencies, and acceptance in OpenSpec immediately. Admit and deliver justified improvements in the same round when they fit the user's intended outcome and existing authority. Assign independent changes when appropriate and route updates to the current owner otherwise.
5. **Extract reusable value concurrently.** Assign a dedicated owner during implementation to examine reusable application and Cloudflare-native code for `theme.tools`, host and system configuration for `install.doctor`, and transferable agent procedures for `agent-skills`. Track each admitted write as an independently owned change with verification. Keep affected documentation and consumers current. Carry forward evidence-backed opportunities that require separate authority or dependencies.
6. **Verify and converge.** Verify requested work and admitted improvements using the applicable repository and production gates. Refresh evidence and check for remaining justified improvements before closure. Follow the [improvement evidence contract](evidence-gated-autonomous-orchestration.md) for convergence and recovery. Commit, push, publish, or change external state under applicable authorization and record the exact state of any pending edge.

For strategy selection, see [parallel swarm planning](../06-build-and-slice-loop/parallel-swarm-planning.md). Related decisions are documented in [context hydration](context-hydration.md), [OpenSpec](openspec-operating-contract.md), and [provider routing](agent-provider-policy.md).
