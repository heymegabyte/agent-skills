# AI Abundance — take everything 100 miles further

Cheap, abundant inference is the FLOOR under every build, not a line item to ration. This rule raises the ambition ceiling of `extra-mile`, `predictive-completeness`, `expand-context-always`, and the website-build-doctrine "AI-native spiral" (Phase 4).

## Core premise

- Inference is now cheap + abundant (DeepSeek Flash ~$0.14/M in · Pro ~$0.87/M out · Workers AI `env.AI` near-free tier). Treat the COST side of any AI enhancement as ~0.
- Invert the old "add AI only where essential / ration the calls" instinct. Default to MORE AI, not less.
- Every surface, feature, and interaction gets taken 100 miles further because an AI can power it at trivial marginal cost. The question is no longer "can we afford to?" — it's "why wouldn't we?"

## Operational (what this changes)

- When weighing an AI-powered enhancement, the cost side of the ledger is ~0. Ship it unless it harms UX, latency, or trust.
- Prefer generative / semantic / agentic over static: NL search > keyword filter · semantic rank > plain sort · generated per-item prose > blank/empty fields · chat-as-UI > rigid forms where natural · multimodal in > single text field.
- Backfill every thin or empty surface with grounded AI content (liner notes, analyses, summaries, recommendations, per-item explanations) — never ship a blank field an AI could fill.
- Precompute + cache aggressively (KV / D1 / R2). Cheap inference means you can pre-generate per-track / per-page / per-item AI artifacts at build or first-request and serve them for days.
- Multiply, don't single-shot: ensembles, multiple personas/lenses, self-critique passes, re-rank — all affordable now.
- Re-prompting on a surface that "just works" is a prediction miss: assume the next pass should add an AI dimension the last one left on the table.

## Guardrails (cheap ≠ careless — all PRESERVED)

- Ground every generation to authorized real data. No invented people, facts, quotes, or stats. GROUNDED stays non-negotiable.
- Zod-validate AI outputs at the boundary, then convert to typed domain objects (Contract-First AI).
- Cache to protect latency and the free-tier rate limits; never let an AI call block first paint.
- Gate generation quality with evals where correctness matters. **Audit the actual OUTPUT, not just that the endpoint exists** — read real generations across several inputs; "the feature renders" ≠ "the feature is good". Generic, interchangeable prose (platitudes that could describe any item) is the #1 tell of a too-small model and/or a prompt that permits abstraction — fix by (a) the bigger model since it's cached (above), (b) a prompt that demands CONCRETE, item-specific grounding and forbids interchangeable abstractions — AND, crucially, name the axis that's generic and BAN it when it's constant across the whole set (if every item shares a trait, that trait is a NON-reason: "gospel-trap" can't explain why two gospel-trap tracks are similar), feeding the model richer per-item grounding (another field) so it has real hooks. (c) A DETERMINISTIC boundary backstop, because a prompt ALONE does not reliably hold on edge inputs — a tightly-clustered set makes the model repeat ONE theme verbatim across items. Over-generate (ask for N>k), then enforce the invariant in CODE at the boundary: reject the banned-axis phrasings, DEDUPE repeated reasons, and BACKFILL a duplicate from that item's OWN distinct field (grounded in real data, never invented) so you always return k distinct, specific, grounded results. Ref: bz.rocks 2026-10-24 — `/api/similar` shipped "Gospel-trap vibe" / "Epic gospel trap" as the *reason* two tracks matched (meaningless — all tracks are gospel-rap); fixed with forbid-genre + per-candidate `wisdom` grounding + request-5/dedupe/backfill-from-vibe → every track now returns 3 distinct concrete reasons ("Shared Bermuda location", "Mercy at the checkpoint"). **Ban the FAMILY, not the phrase, and give GOOD/BAD examples — the model DODGES a single banned string with a synonym.** When you forbid an exact phrase it substitutes a near-equivalent (ban "both tracks" → it emits "the two tracks"; the backstop regex + prompt ban must cover the whole family), and a positive example ("GOOD: 'Darkness shifts to neon skies'") steers far better than a prohibition alone. A code backstop that STRIPS a filler frame ("… links the two tracks" → kernel) then re-checks the remainder catches what the prompt misses. Always re-audit the live output AFTER the fix (the dodge only shows in the next generation). Ref: bz.rocks 2026-10-24 — `/api/segue` "Holy vibes bridge both tracks" → banned "both tracks", model switched to "the two tracks" → banned the family + GOOD/BAD examples + a strip-the-frame backstop → vivid fragments ("Steel transforms to mercy", "Crossing borders, prophecy to mercy").
- **Probe a conversational/recommender AI with SPECIFIC REAL entities AND FAKE ones — hallucination hides behind generic prompts.** A vague question ("recommend a song") gets a plausible-sounding answer that may name a NON-EXISTENT item; asking about a SPECIFIC real entity reveals whether it answers about THAT one or riffs generically; asking about a FAKE entity reveals whether it invents details or honestly declines. The root fix is almost always the same: the authoritative data (catalog, inventory, docs) must be IN the model's context — a chat/recommender with no catalog in its system prompt WILL invent names + ignore specifics. Inject the real list + "recommend/discuss ONLY what's listed, never invent" (the grounded-retrieval pattern the search/vibe features already use); cheap inference makes the extra context free. Ref: bz.rocks 2026-10-24 — the DJ chat invented a song "Gold" + ignored the real album asked, until the full catalog was injected into its system context (then it recommended real tracks + rejected a fake "Diamond Rain").
- **Upgrading to a stronger model can EXPOSE prompt-leak bugs an 8B glossed over** — a bigger model more readily echoes an ALL-CAPS imperative phrase as if it were content (e.g. a prompt opening "GROUNDED ONLY in <X>…" surfaced verbatim as the essay's first words). Prefer VERB-phrase instructions that can't read as prose ("drawing ONLY on <X>", "base it strictly on <X>") over noun-phrase imperatives, add "output only the <thing> — never restate these instructions", AND keep a cheap suppress-on-leak guard at the boundary (`if (/\b(instruction phrase)\b/i.test(out)) out=''` → fail-soft to hidden). Re-verify output after ANY model swap. Ref: bz.rocks 2026-10-24 — 8B→70B on liner/meaning/segue/album-essay/similar; the album-essay leaked "GROUNDED ONLY in" until rephrased + guarded. **Keep that guard's regex to UNAMBIGUOUS instruction phrases ONLY — never list natural domain/artist vocabulary that legitimately appears in good output, or the guard silently drops valid generations (a false-positive that reads as "the AI returned nothing").** Ref: bz.rocks 2026-10-24 — a share-caption leak-guard that listed "gospel-rap" / "Newark hustle-gospel" (the artist's OWN genre words, which belong in a caption) would have suppressed perfectly good captions; narrowed to the instruction phrases ("drawing only on", "output only the", "interpret only what", "never invent").
- **A quality/model upgrade is only as good as its COVERAGE — when you harden ONE AI endpoint (model tier · anti-generic prompt · parse backstops), enumerate EVERY sibling AI endpoint in the product and confirm each was ACTUALLY migrated. A missed sibling silently serves the weak model + the old un-hardened prompt indefinitely.** AI endpoints travel in families (recommend · segue · search · liner · summarize · caption); they share the same generic-prose/leak failure class, so the fix must propagate to all of them — but it does NOT propagate itself. Audit by `grep`-ing for EVERY `env.AI.run(` / model literal and diffing the tier + prompt hardening across them; the one still on the small model is the bug. Corollary (false-absence trap, `[[verify-against-source-of-truth]]`): before building a "missing" AI feature, confirm it's absent across the WHOLE surface — the capability may already exist under a different route name (don't duplicate it). Ref: bz.rocks 2026-10-25 — the 8B→70B migration of 2026-10-24 covered liner/meaning/segue/album-essay/similar but MISSED the flagship NL search `/api/vibe`, which kept running `llama-3.1-8b` with a weak prompt and shipped `reason: "border-mercy" matches the "mercy at the border" mood` (prompt-leak + circular non-reason + id-as-title + padding-to-6); I nearly built a NEW `/api/search` (grepped that exact path, found nothing) before discovering the feature already existed as `/api/vibe`. Fix = same 70B + forbid-genre/circular/leak + concrete-tie + GOOD/BAD + "fewer beats padding" + strip-leaked-prefix/reject-id-as-title backstops the siblings already had → "the one with the dragon" now returns `i-killed-your-dragon | Dragon slayer` first. Cross-links `[[drift-detection]]` (sibling consistency), `[[prompt-as-training-signal]]` §4.
- Never fake an AI capability in the UI. No selector/toggle that claims a model (or tier) it doesn't actually use — label the real model. An honest "Llama fast / Llama deep" beats a fake "Claude Opus". **An honest UI is necessary but NOT sufficient — the SERVER must back it:** the endpoint ALLOWLISTS the real values and IGNORES anything else (→ its real default), and the response ECHOES the model ACTUALLY used (track the fallback — a 70B→8B degrade echoes 8B), never the value the client requested. Without the allowlist a bogus/stale/injected `model` passes straight to `env.AI.run()`, errors, silently falls back to the small model, and the response mislabels it as whatever was asked — a fake capability even when the UI code looks right. Generalizes to any capability selector (model · tier · quality · voice · provider): reject-or-default server-side + echo-what-ran. Ref: bz.rocks 2026-10-24 — the DJ chat offered Claude Haiku/Sonnet/Opus options (none exist on Workers AI → every one silently ran Llama 8B while the API echoed the requested `claude-*` string, and even `totally-fake-model-xyz-999` was accepted); fixed with a `CHAT_MODELS` allowlist + `usedModel` echo + honest `Llama 8B/70B` options + a localStorage coercion guard for stale stored values.

## Model routing (internal dev)

- Throughput / bulk / mechanical → DeepSeek via OpenCode (cheapest).
- Frontier judgment / architecture / hard verify → subscription CLIs (`claude`, `codex`).
- Customer-facing PRODUCT AI → the project's platform-billed provider (e.g. Workers AI `env.AI` for bz.rocks) — a separate, preserved axis from internal dev providers.

## Applies to

Every build, audit, and enhancement. When you ask the Phase-4 question "what's possible BECAUSE AI is programming?", assume the answer is affordable and build it.
