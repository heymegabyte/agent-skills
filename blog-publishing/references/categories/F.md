# F — SHARED COMPONENTS AND DESIGN SYSTEM: 30 REUSABLE UPGRADES

Load this category only when the article task, affected runtime boundary, or release risk selects it. The directives below are exact authorized requirements. Record applicability and live evidence in the adopting repository; policy presence is not runtime verification.

- **F01.** Versioned brand contract. Define a validated manifest for colors, typefaces, spacing, radii, imagery direction, and editorial tone. Support explicit per-site overrides so articles, editor previews, illustrations, and the component catalog inherit the same approved identity.
- **F02.** Semantic theme tokens. Express surface, foreground, border, accent, focus, and status colors through semantic tokens rather than scattered values. Include light and dark appearances where supported, and verify text, controls, and charts against their actual backgrounds.
- **F03.** Editorial typography scale. Standardize heading hierarchy, paragraph measure, line height, captions, code, quotations, and tabular numbers. Provide responsive typography rules that preserve comfortable reading, deliberate rhythm, and clear distinctions between narrative, evidence, and supporting context.
- **F04.** Constrained page composition. Build a small set of editorial layouts with controlled widths and spacing, including full-width figures and balanced comparison sections. Let authors select purposeful layouts while preventing arbitrary styling that breaks brand coherence or mobile reading.
- **F05.** Typed block registry. Maintain one schema registry for supported article blocks, their versions, renderer, editor adapter, validation, and migration. Reject unknown unsafe blocks gracefully and expose the same supported capabilities to agents, authors, and previews.
- **F06.** Shared rendering contract. Reuse block definitions and presentation primitives across published pages, Plate editing, previews, and export. Exercise representative documents across those surfaces so spacing, citations, data, and media remain consistent through the complete authoring lifecycle.
- **F07.** Semantic foundations. Establish accessible buttons, links, headings, lists, dialogs, inputs, and tables before adding decorative variants. Give every foundation documented keyboard and screen-reader behavior so advanced editorial components inherit reliable interaction patterns.
- **F08.** Citation reference primitive. Render numbered references as genuine fragment links with stable IDs and accessible labels. Enhance activation with smooth scrolling when permitted, preserve browser history and keyboard navigation, and provide a visible focus treatment at the destination.
- **F09.** Bibliography widget. Create a bottom-of-article source list with titles, publishers, publication dates when known, retrieval dates, and source URLs. Support multiple backlinks to citing passages and make numbering follow document order without duplicating source records.
- **F10.** Reusable figure frame. Standardize media, caption, alt text, source credit, methodology note, and expandable long description within one figure component. Compose image, chart, diagram, and authentic screenshot variants through this frame instead of creating isolated wrappers.
- **F11.** Finite chart grammar. Offer a deliberate set of line, bar, distribution, scatter, composition, and interval charts with validated typed data. Centralize axes, legends, units, annotations, source links, and accessible summaries to avoid bespoke misleading chart implementations.
- **F12.** Visual authenticity treatment. Define visible labels for conceptual illustrations, generated exemplars, authentic captures, measured results, and forecasts. Keep that distinction in captions and metadata so attractive visuals never imply evidence or firsthand experience they do not contain.
- **F13.** Asset lineage records. Attach stable asset IDs, source permissions, generation model/version, prompt, cost, dimensions, approval status, and related citations to media. Preserve these records through reuse and export, while keeping credentials and internal secrets outside published metadata.
- **F14.** Optimized image primitive. Generate responsive derivatives and modern formats, declare intrinsic dimensions, and use meaningful alt text. Give the hero appropriate loading priority and defer below-the-fold assets; retain high-resolution originals separately from routine page delivery.
- **F15.** Safe content boundaries. Render approved structured blocks through explicit components and sanitize imported HTML. Allowlist embed hosts and validate URLs, protocols, and dimensions; do not execute arbitrary scripts, generated JSX, or event handlers from article content.
- **F16.** Composable comparison tables. Provide sortable and static table modes with captions, semantic headers, units, citations, and clear missing-value handling. Support responsive stacking only when relationships remain understandable, and offer a downloadable source table for substantial datasets.
- **F17.** Unified editorial callouts. Use one configurable callout family for takeaways, definitions, caveats, recommendations, and evidence notes. Distinguish variants through wording, icon, and contrast-safe styling; limit competing emphases so a page retains a clear visual hierarchy.
- **F18.** Progressive disclosure. Supply accessible accordions, glossary popovers, and optional detail panels for secondary explanations. Keep the main answer visible in initial HTML, provide sensible defaults, and preserve access to essential evidence without requiring hover or animation.
- **F19.** Sequence component family. Compose process steps, milestones, and timelines from shared ordered-list semantics and presentation primitives. Support compact and expanded treatments, clear current-state labels, and source links without introducing incompatible interaction patterns for each article.
- **F20.** Calculator component contract. Separate validated inputs, pure calculation functions, units, assumptions, and presentation. Include worked examples and boundary cases, show a useful initial result or explanation, and ensure user changes never silently rewrite cited source data.
- **F21.** Container-aware responsiveness. Adapt editorial blocks to their available container, including embedded and split-column contexts. Specify behavior for narrow screens, zoom, long labels, and landscape devices so reusable components remain useful beyond a single blog template.
- **F22.** Keyboard and focus stories. Document tab order, escape behavior, focus restoration, visible focus, and nested interactive states in Storybook. Test citation jumps, dialogs, disclosures, and author controls with keyboards as well as pointing devices.
- **F23.** Motion preferences. Centralize animation durations and reduced-motion behavior. Replace animated citation scrolling and large positional transitions with immediate navigation when the user requests reduced motion, while preserving destination focus, context, and useful feedback.
- **F24.** Equivalent data access. Pair complex figures with concise summaries and accessible detailed descriptions or data tables. Ensure keyboard and screen-reader users can inspect values, units, relationships, and uncertainty without depending on canvas pixels or color discrimination.
- **F25.** Static-first delivery. Render narrative, citations, tables, and ordinary figures as meaningful server-generated HTML. Load interactive chart controls, calculators, and editing code only where needed so richer article design does not impose an editor-sized bundle on readers.
- **F26.** Adversarial content fixtures. Add stories containing long titles, many citations, absent images, loading failures, large tables, localization, bidirectional text, and empty states. Use real editorial edge cases to verify resilience beyond visually convenient demonstration content.
- **F27.** Targeted visual regression. Capture representative brand variants and critical viewports for shared primitives and complete article compositions. Review intentional changes and flag clipping, overflow, missing captions, citation collisions, or theme drift before publishing template updates.
- **F28.** Interaction and accessibility gates. Run Storybook interaction tests and automated accessibility checks in CI, awaiting asynchronous content before assertions. Add manual checks for complex figures and meaningful reading order, because automated checks cannot establish full accessibility.
- **F29.** Measured performance budgets. Define and monitor page transfer, image weight, layout shift, and interaction budgets against representative devices. Attribute regressions to components, reserve media space, and prefer lightweight replacements when a visual adds more cost than explanatory value.
- **F30.** Maintained component catalog. Publish versioned usage guidance, examples, content constraints, migration notes, and deprecations in ui.theme.tools or the configured catalog. Keep package exports stable and require agent authors to choose existing supported compositions before proposing new components.
