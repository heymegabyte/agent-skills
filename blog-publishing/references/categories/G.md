# G — PLATE / SLATE AUTHORING AND PAGE COMPOSITION

Load this category only when the article task, affected runtime boundary, or release risk selects it. The directives below are exact authorized requirements. Record applicability and live evidence in the adopting repository; policy presence is not runtime verification.

- **G01.** Use one versioned, typed Slate document schema as the article source of truth. Register every supported block, inline, mark, citation, and asset type in a shared renderer/editor contract so editing and reading preserve identical content.
- **G02.** Render published articles through the documented Plate static rendering path with server-safe plugins. Load the interactive editor only when the visitor can edit; retain the same typography, component registry, source IDs, and asset references across both presentations. [S18]
- **G03.** Open existing articles in a fully integrated front-end Plate authoring experience for authorized editors, with visible editing controls and current draft status. Hydration or viewing must never create revisions, overwrite stored content, or publish a draft.
- **G04.** Put a large, clearly labeled “+ New article” button at the top of every integrated blog homepage, shown only to authorized editors. Support keyboard activation, visible focus, loading feedback, and a generous touch target.
- **G05.** Provide Google, GitHub, and email magic-link sign-in entry points that return users to their intended article or creation flow. Show an explicit access-denied state when authentication succeeds but the user lacks editorial permissions for that website.
- **G06.** Import existing HTML, Markdown, MDX, or CMS articles through a previewable migration with retained originals, mapping reports, and round-trip checks. Preserve unsupported material visibly or quarantine it for repair; never silently discard or automatically overwrite an existing article.
- **G07.** Show draft, review, scheduled, and published states distinctly inside the editor. Editing a published article creates or updates its draft; the currently published snapshot remains visible until a deliberate, authorized publishing operation replaces it.
- **G08.** Implement debounced, content-change autosave with clear saving, saved, offline, and failed indicators. Keep the editor instance stable; exclude selection-only changes from saves and preserve IME composition, undo history, and cursor position during acknowledgments.
- **G09.** When a newer server revision conflicts with local changes, present an understandable comparison and recovery choice. Preserve both versions and the user’s unsent work; never hide a conflict behind a successful-looking save notification.
- **G10.** Offer recoverable offline drafts, scoped to the signed-in account, website, and document. Explain local recovery availability, reconcile after reconnecting, and prevent a different user on the same device from inheriting another author’s content.
- **G11.** Add a revision timeline with author, timestamp, meaningful summary, visual comparison, and restore controls. Restoration creates a new revision, making it possible to recover previous content without erasing the history of intervening changes.
- **G12.** Implement convergent normalization and explicit schema migrations for every custom node. Follow Slate’s inline, void, text-child, and block constraints; perform multi-step structural transformations without intermediate normalization and expose unsupported versions through a repair interface. [S19]
- **G13.** Give persistent blocks, source records, assets, claims, and citation occurrences stable identifiers. Reordering preserves identity; duplicating or importing content remaps identifiers deliberately so anchors, review comments, and citations do not accidentally target the wrong instance.
- **G14.** Insert citations through a source picker linked to a claim ledger. Store stable source and occurrence identifiers in document nodes, derive displayed numbers from document order, and reuse a source without duplicating its bibliography record.
- **G15.** Build the bottom-of-article Sources widget from cited source records, with titles, publishers, publication dates when known, access dates, URLs, and occurrence backlinks. Unused research sources stay out of the displayed bibliography unless explicitly labeled further reading.
- **G16.** Make citation numbers real fragment links that animate to their source entry when motion is permitted. Respect reduced-motion preferences, sticky-header offsets, keyboard focus, and browser history; provide clear backlinks to every place the source was cited.
- **G17.** Show evidence status beside factual claims and statistics while editing. Material changes to a supported claim invalidate its previous verification until rechecked; let editors inspect the relevant source excerpt and resolve missing or contradictory support.
- **G18.** Offer an allowlisted component palette connected to the existing Storybook registry, including comparisons, callouts, timelines, checklists, stat panels, diagrams, and interactive explainers. Store validated component names and typed properties instead of arbitrary executable MDX or JavaScript.
- **G19.** Provide brand presets for spacing, type scale, colors, borders, surfaces, and illustration treatment. Let authors choose supported page compositions while keeping responsive behavior and public/editor appearance consistent with the selected website’s design system.
- **G20.** Add structured figure and chart blocks with editable data, units, labels, captions, source references, and methodology notes. Render exact quantitative graphics deterministically and expose an accessible data table; reserve generated illustrations for non-evidentiary visual storytelling.
- **G21.** Provide media controls for asset selection, crop, focal point, aspect ratio, descriptive alternative text, captions, credits, and source links. Store durable asset identifiers so replacing a derivative does not silently alter citations or article history.
- **G22.** Give each visual block an explicit purpose, generation brief, brand reference, and approval state. Offer economical variation and regeneration controls with estimated cost, while allowing reuse of an approved asset when another generation adds little reader value.
- **G23.** Provide searchable slash commands, keyboard shortcuts, block conversion, and reusable article sections using documented Plate extension points. Keep menus keyboard-operable, preserve selection during insertion, and prevent unsupported combinations that break the canonical document schema.
- **G24.** Make table authoring practical with header cells, row and column controls, sorting where appropriate, captions, source references, and a readable small-screen presentation. Preserve the meaning and order of data when exporting or changing a table’s appearance.
- **G25.** Add a live outline, stable heading anchors, section navigation, and deliberate block reordering. Help authors see the page’s argument and visual rhythm while preserving anchor references, selection, nested structures, and attached comments through moves.
- **G26.** Support anchored comments, suggested edits, assignment, resolution, and review status. Track when a passage is deleted or substantially rewritten, showing detached discussion honestly instead of silently attaching feedback to unrelated text.
- **G27.** Make AI assistance propose scoped, reviewable diffs for selected passages, sections, metadata, and component properties. Show affected claims and sources, protect against stale-document suggestions, and support individual accept, reject, and undo actions.
- **G28.** Offer optional Yjs collaboration with presence, remote cursors, and reconnect feedback through a tested transport adapter. Initialize the shared document once, clean up providers correctly, and keep ephemeral presence separate from durable article content. [S47]
- **G29.** Include an editorial sidebar for title, description, slug, canonical URL, primary keyword, related terms, internal links, hero assets, and scheduling. Display research-backed guidance and warnings without turning arbitrary keyword-density targets into mandatory insertion rules.
- **G30.** Pin the installed Plate, Slate, and collaboration package versions and verify extension APIs against matching documentation. Keep reusable integrations compatible with open-source licensing; require separate entitlement before incorporating commercially licensed Plate Plus components or templates. [S50]
